# 论文协作区与知识区关系说明

> 版本: v1 | 生成时间: 2026-05-04

## 核心原则

```text
长期知识库 = 稳定知识、理论基础、文献结论、术语、公式、方法论
论文协作区 = 当前或未来某篇论文的构造、证明、想法、实验、写作过程
```

二者不是单向关系，而是双向关系:

```text
长期知识库 -> 支撑论文写作
论文写作 -> 产生新知识 -> 反向沉淀进长期知识库
```

## 论文协作区结构

```
04_论文协作区/
  00_论文项目总索引.md      — 所有论文项目的索引
  01_当前论文项目/          — 当前活跃的论文项目
    Eurocrypt2027/          — 当前论文
  02_未来论文项目模板/      — 新论文项目模板
  03_论文知识沉淀记录/      — 从论文到知识库的反向沉淀
```

### 单个论文项目内部结构（双层）

```
论文项目名/
├── 00_项目管理/  ... 10_发布快照/    ← 论文材料区（作者写论文用）
├── 11_AI工作区/                      ← AI 接手/理解/检查用
│   ├── 00_接手说明/  (项目总览、AI协作上下文、核心材料索引)
│   ├── 01_项目理解/  (当前理解、论文主线、写作路线、符号约定)
│   ├── 02_待办与人工确认/
│   ├── 03_P0核实/
│   ├── 04_证明与噪声检查/
│   ├── 05_Related_Work辅助/
│   ├── 06_知识沉淀候选/
│   └── 99_归档候选/  (一次性计划、重复文件副本)
└── README.md
```

> 根目录只保留 README.md + 一级目录，不堆放散文件。
> AI 入口文件、一次性计划、审计报告归入 11_AI工作区，不散落在论文材料区。

## 知识入库接口

```
11_知识入库接口/
  新知识候选箱.md           — 来自论文或新阅读的知识候选
  入库审核规则.md           — 什么可以进入长期知识库
  入库状态看板.md           — 当前所有候选知识的状态
```

## 论文知识沉淀流程

```text
论文项目中产生想法
  -> 记录到论文协作区
  -> 判断是否有长期价值
  -> 放入 新知识候选箱
  -> 生成 candidate card
  -> 标注来源论文 project paper_id
  -> 标注 idea_id
  -> 标注是否已验证
  -> 如果通过验证，发布到正式知识库
  -> 更新术语表/公式表/原子问答/关系图
  -> 保留回链到原论文项目
```

## 知识状态

| 状态 | 含义 |
|------|------|
| draft_idea | 草稿想法 |
| candidate_knowledge | 候选知识 |
| needs_validation | 需要验证 |
| validated | 已验证 |
| published_to_kb | 已发布到知识库 |
| deprecated | 已废弃 |
| negative_result | 失败经验/反例/不推荐路线 |

## 边界区分

### 论文协作区适合放:
- 未完成的核心想法
- construction 草稿
- proof 草稿
- 实验计划
- 写作任务 / TODO
- 暂未验证的 conjecture
- 当前论文局部定义
- 当前论文临时 notation

### 长期知识区适合放:
- 已验证的定义
- 已整理的理论基础
- 可复用的证明技巧
- 可复用的技术模块
- 稳定术语 / 稳定公式
- 文献结论 / 原子问答
- 可跨论文复用的关系图

### 过渡区 (11_知识入库接口):
- 还没完全确认但可能值得沉淀的内容
