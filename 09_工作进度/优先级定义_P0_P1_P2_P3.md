# 任务优先级定义：P0 / P1 / P2 / P3

> 版本: v1 | 生成时间: 2026-05-04 | 适用范围: 全知识库 + 论文项目

---

## P0 — 最高优先级 / 必须优先处理

P0 指直接影响论文 correctness、安全性、噪声分析、参数解释的问题。

在本知识库和论文项目中，P0 包括:
- 直接影响当前论文 construction 是否说得清楚的问题；
- 直接影响 correctness proof 的问题；
- 直接影响安全性、噪声分析、参数解释的问题；
- 如果不确认，可能导致后续知识卡片、RAG、论文写作沿错误方向扩大的问题；
- 已在知识卡片中标记 needs_human_review: true 且影响主线的内容。

**P0 示例:**
- 当前论文使用 coefficient split / slot-preserving split / 混合方案
- CKKS slot 和 BGV/BFV CRT slot 是否混用
- BFV / CKKS Rescale 术语是否混用
- PaCo 中 p 和 Delta 的精确区别
- GHPS Duality / Good Bases 是否影响 field switching 正确性和噪声分析
- 当前论文环参数 m, m0, r 是否满足构造要求
- 当前论文密文定义在 R 还是 R^v 上

**P0 执行规则:**
- P0 必须先核实、标注来源、必要时对照原论文
- P0 未解决前，不进行大规模 embedding
- P0 未解决前，不把相关结论写成确定知识

---

## P1 — 重要问题 / 需要处理但可稍后

P1 指重要但不是当前阻塞项的问题。

**P1 示例:**
- 某些术语需要更精确
- 某些公式需要补充来源
- 某些 related work 需要归类
- 某些证明细节需要后续补读
- 某些实现细节需要和 OpenFHE 或论文原文对照

**P1 执行规则:**
- P1 在 P0 核实完成后处理
- 可以先标注但不阻塞 P0 工作
- 不影响当前论文主线的 P1 可以延迟

---

## P2 — 补充问题 / 完备性问题

P2 指影响知识库完整性，但暂时不影响当前论文主线的问题。

**P2 示例:**
- 后量子旁线材料
- 格签名材料
- 一般背景论文
- 不是当前 construction 必需的补充知识
- 未来可能有用但目前不阻塞论文的资料

**P2 执行规则:**
- P2 在 P0 和 P1 完成后处理
- 可以做轻读但不做精读
- 生成简单卡片即可，不展开原子问答

---

## P3 — 参考问题 / 低优先级

P3 指可选参考资料、暂时不处理也不会影响当前论文和知识库主线的问题。

**P3 示例:**
- 边缘参考材料
- 旧版本重复材料
- 暂时看不出与当前论文关系的论文
- 仅供以后学习的背景资料

**P3 执行规则:**
- P3 不主动处理
- 用户明确要求时再处理
- 可在全库 Batch 规划中列出但不排期

---

## 执行原则

```text
优先级排序: P0 -> P1 -> P2 -> P3
```

- 不要把 P0/P1/P2/P3 平均处理
- P0 必须先核实、标注来源
- P0 未解决前，不大规模 embedding
- 不要因为 P2/P3 的量大而延迟 P0
- 每批次开始前检查当前 P0 状态

## 状态标记

在知识卡片和原子问答中使用以下标记:
- `needs_human_review: true` — 需要人工确认（P0/P1 级别）
- `confidence: low/medium/high` — 置信度
- `claim_source_type` — 声明来源类型（原文/笔记/推断）
