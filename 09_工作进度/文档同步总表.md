# 文档同步总表

> 版本: v1 | 生成: 2026-05-04
> 用途: 当发生某类变化时，必须同步更新哪些文档。

---

## 变化类型 → 同步操作

### 1. 新增源文件

| 必须更新 | 位置 |
|----------|------|
| 导入清单 | `00_导入记录/导入清单.md` |
| canonical_source_manifest | `09_工作进度/canonical_source_manifest.jsonl` |
| 已处理文件记录 | `09_工作进度/已处理文件.jsonl` |
| 资料清单总览 | `00_资料清单/资料清单总览.md` |

**是否需要 embedding？**
- 仅新增源文件，不生成 ready chunks → ❌ 不需要
- 新增源文件并生成 ready 卡片/Q&A/chunks → ✅ 需要重建 embeddings 和 BM25

---

### 2. 新增知识卡片

| 必须更新 | 位置 |
|----------|------|
| 卡片文件 | `02_知识卡片/` (JSON + MD) |
| canonical_card_manifest | `09_工作进度/canonical_card_manifest.jsonl` |
| 全局索引 | `09_工作进度/全局知识卡片索引.md` |
| ready/defer 清单 | `06_RAG入库准备/RAG_ready_defer清单.md` |

**是否需要 embedding？**
- 卡片 `rag_status=ready` → ✅ 切 chunk → 重建 embeddings + BM25
- 卡片 `rag_status=defer` 或 `candidate` → ❌ 不需要

---

### 3. 新增原子问答

| 必须更新 | 位置 |
|----------|------|
| Q&A 文件 | `03_原子问答/` |
| canonical_qa_manifest | `09_工作进度/canonical_qa_manifest.jsonl` |
| 全局索引 | `09_工作进度/全局原子问答索引.md` |
| ready/defer 清单 | `06_RAG入库准备/RAG_ready_defer清单.md` |

**是否需要 embedding？**
- Q&A `rag_status=ready` → ✅ 切 chunk → 重建 embeddings + BM25
- Q&A `rag_status=defer` → ❌ 不需要

---

### 4. 修改 ready card / ready Q&A 正文

| 必须更新 | 位置 |
|----------|------|
| 对应文件 | `02_知识卡片/` 或 `03_原子问答/` |
| canonical manifest | `09_工作进度/canonical_card_manifest.jsonl` 或 `canonical_qa_manifest.jsonl` |
| ready chunks | `06_RAG入库准备/chunks/` |
| embeddings | `06_RAG入库准备/api_rag/data/` |
| BM25 索引 | `06_RAG入库准备/api_rag/data/` |
| Baseline 版本记录 | `06_RAG入库准备/RAG_Baseline_v1.0_记录.md` |

**是否需要 embedding？**
- ✅ **需要**。只要 ready chunk 文本变化，就必须重建 embeddings + BM25。

---

### 5. 只修改 README / SOP / 项目说明

| 必须更新 | 位置 |
|----------|------|
| 对应说明文档 | 原地修改 |

**是否需要 embedding？**
- ❌ 不需要，除非这些说明文档也被纳入 RAG chunks。
- 当前 README 和 SOP 均未进入 RAG chunks。

---

### 6. 新增论文 idea / candidate

| 必须更新 | 位置 |
|----------|------|
| 论文项目候选目录 | `04_论文协作区/当前项目/09_知识沉淀候选/` |
| candidate 总表 | `11_知识入库接口/candidate_knowledge总表.md` |
| AI 工作区候选 | `当前项目/11_AI工作区/06_知识沉淀候选/` |

**是否需要 embedding？**
- ❌ 默认不需要。
- candidate 不进入 RAG ready。
- 只有作者验证后升级为正式卡片 → 视 `rag_status` 决定。

| 必须更新 | 位置 |
|----------|------|

- ❌ 实验原始日志不需要 embedding。

### 8. 新论文项目

| 必须更新 | 位置 |
|----------|------|
| 项目总索引 | `04_论文协作区/00_论文项目总索引.md` |

- ❌ 新论文项目材料默认不进 RAG ready。
- validated 后沉淀为长期知识库卡片时 → 视 `rag_status` 决定。

## 速查：是否需要 embedding？

| 操作 | embedding? |
|------|:--:|
| 新增源文件（不生成卡片） | ❌ |
| 新增 ready 卡片 | ✅ |
| 新增 ready Q&A | ✅ |
| 修改 ready card/Q&A 正文 | ✅ |
| 新增 candidate | ❌ |
| 新增实验原始日志 | ❌ |
| 改 README / SOP | ❌ |
| 移动/复制文件 | ❌ |
| 新论文项目（沉淀前） | ❌ |
| 修正核心术语（如 C2S/S2C） | ✅ |
| 删除 ready chunk | ✅ |
