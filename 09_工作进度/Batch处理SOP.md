# Batch 处理 SOP (标准操作流程)

> 版本: v1 | 生成: 2026-05-04 | 适用范围: 所有 FHE 知识库 Batch

## Batch 定义

一个 Batch 是一组主题相关的文件集合，经过统一流程处理后产出一组知识卡片、原子问答、术语和公式。

---

## 标准处理流程

### Phase 1: 源文件导入

1. 确定 Batch 范围（文件列表或目录）
2. 复制文件到 `01_源文件库/` 对应子分类（不移动/不删除原文件）
3. 在 `00_导入记录/原始路径到库内路径映射.jsonl` 注册 source_id
4. 更新 `00_导入记录/导入清单.md`

### Phase 2: 轻度阅读与分类

1. 对每个文件做轻读（扫描结构、提取关键词）
2. 标记文件类型（pdf/md/tex/txt/note/translation）
3. 分配子主题标签（代数基础/FHE方案/核心技术/Bootstrapping/...）
4. 标记 ingest_decision（精读/轻读/跳过/待判断）

### Phase 3: 精读与知识卡片生成

1. 对标记为"精读"的文件深度阅读
2. 生成知识卡片 JSON（card_id, title, knowledge_points, formulae, terminology, relations）
3. 同步生成 MD 版本
4. 标注 needs_human_review / confidence / claim_source_type

### Phase 4: 原子问答生成

1. 基于知识卡片生成原子问答（每卡 5 条）
2. 每条包含: id, question, answer, source_id, card_id, difficulty
3. 标注需要人工确认的问答

### Phase 5: 术语和公式抽取

1. 从卡片中抽取术语 → 写入术语表
2. 从卡片中抽取公式 → 写入公式表
3. 每个术语/公式保留 source_id 追溯

### Phase 6: 关系图更新

1. 检查新内容是否影响已有关系图
2. 更新 `05_知识关联/` 中的关系图
3. 标记新增来源

### Phase 7: 路径审计

1. 检查所有生成文件中的路径引用
2. 确保使用 `01_源文件库/...` 标准路径
3. 禁止嵌套路径、旧目录路径、绝对路径

### Phase 8: 修正版生成

1. 审核知识卡片质量
2. 修正术语不一致、公式错误
3. 修正路径问题
4. 生成修正版目录（v2/v2.1）

### Phase 9: 发布到正式知识库

1. 将知识卡片按学科分类到 01/02/03/04 知识库
2. 将原子问答按学科分类
3. 交叉引用处理（主归属 + 索引引用）
4. 保持源目录不变（快照保留）
5. 写入发布日志

### Phase 10: RAG 入库准备

1. 确认所有 P0 问题已核实
2. 确认所有 needs_human_review 已处理
3. 生成 chunk 切分方案
4. 生成 embedding 输入样例
5. 暂不实际调用 embedding API

---

## 重要原则

- 不修改/删除/移动临时资料池
- 不覆盖已有文件（冲突时加版本号）
- 每条知识保留 source_id 追溯
- P0 问题未解决前，不进入 RAG
- 所有操作写入日志

---

## 内容来源类型

Batch 内容可能来自:
1. 外部论文 PDF
2. 用户的理论笔记（md/tex）
3. 当前论文草稿
4. 新开论文项目
5. 实验结果
6. 失败尝试 / negative result
7. 新的 proof trick
8. 新的 construction idea

不同类型的知识需经过不同的候选→验证→发布流程。
