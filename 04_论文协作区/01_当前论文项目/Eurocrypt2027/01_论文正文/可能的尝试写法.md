对，这样写会更自然，而且我觉得你可以把它提升成一个更高层次的理论框架，而不是只说“CKKS bootstrapping 这个例子可以拆”。

你现在可以把核心理论抽象成：

[
\boxed{
\text{split-compatible linear--coordinatewise nonlinear--linear circuits}
}
]

也就是一种“线性变换 + 逐坐标非线性 + 线性变换”的可分解结构。

---

## 1. 你可以把主定理升维成 general criterion

设大维度上的计算是：

[
F_N
===

L_N^{(2)}
\circ
\Phi_N
\circ
L_N^{(1)},
]

其中：

[
\Phi_N
======

\phi^{\otimes s_N}
]

是逐坐标非线性：

[
\Phi_N(z_0,\ldots,z_{s_N-1})
============================

(\phi(z_0),\ldots,\phi(z_{s_N-1})).
]

然后有 split/merge：

[
\Split_k: V_N\to V_n^{\oplus k},
\qquad
\Merge_k: V_n^{\oplus k}\to V_N.
]

如果存在 leaf 线性变换：

[
L_n^{(1)},\quad L_n^{(2)}
]

以及某个坐标重排 (\Pi_k)，满足：

[
\left(\bigoplus_{r=0}^{k-1}L_n^{(1)}\right)
\circ
\Split_k
========

\Pi_k
\circ
L_N^{(1)},
]

以及：

[
\Merge_k
\circ
\left(\bigoplus_{r=0}^{k-1}L_n^{(2)}\right)
\circ
\Pi_k
=====

L_N^{(2)},
]

那么因为：

[
\Phi_N\circ\Pi_k
================

\Pi_k\circ\Phi_N,
]

所以可以推出：

[
\boxed{
F_N
===

\Merge_k
\circ
\left(
\bigoplus_{r=0}^{k-1}
L_n^{(2)}
\circ
\Phi_n
\circ
L_n^{(1)}
\right)
\circ
\Split_k.
}
]

这就是你的更高层次理论。

## 2. CKKS bootstrapping 是这个 framework 的一个实例

在你的场景里：

[
L_N^{(1)}=\CtwoS_N,
]

[
\Phi_N=\EvalMod_N,
]

[
L_N^{(2)}=\StwoC_N.
]

所以：

[
F_N
===

\StwoC_N
\circ
\EvalMod_N
\circ
\CtwoS_N.
]

leaf 上：

[
F_n
===

\StwoC_n
\circ
\EvalMod_n
\circ
\CtwoS_n.
]

然后你的 factored 版本就是：

[
\boxed{
F_{N,k}^{\mathrm{fac}}
======================

\Merge_k
\circ
\left(
\bigoplus_{r=0}^{k-1}
F_n^{(r)}
\right)
\circ
\Split_k.
}
]

这比只写 CKKS bootstrapping 的一个专门证明更有理论感。

## 3. 这个 framework 的关键不是逐坐标非线性，而是两个线性兼容条件

最重要的是你要强调：

[
\boxed{
\text{非线性逐坐标这件事本身很简单；真正的结构条件是前后两个线性变换要 split-compatible。}
}
]

也就是：

[
\left(\oplus L_n^{(1)}\right)\circ\Split_k
==========================================

\Pi_k\circ L_N^{(1)}
]

和：

[
\Merge_k\circ(\oplus L_n^{(2)})\circ\Pi_k
=========================================

L_N^{(2)}.
]

一旦这两个条件成立，中间的逐坐标非线性自然可以 leaf-wise 执行。

所以你的论文里可以把理论贡献写成：

[
\boxed{
\text{We identify that the CKKS bootstrapping core satisfies the split-compatibility conditions.}
}
]

而不是只说：

[
\EvalMod\text{ is coordinate-wise.}
]

## 4. 更高维度可以怎么解释？

你说“更高的维度”，我觉得可以有三层意思。

### 第一层：更大的 (N)

也就是实验上从：

[
\log N=16
]

到：

[
\log N=17,\ 18.
]

这个层面说明你的 factorization 在更大的 ring degree 上仍然成立，而且更能体现复杂度优势。HERMES 也使用 ring switching 来 decouple 小 degree 和 bootstrapping degree，并强调降低 degree 的限制是 lowered degree 和对应 modulus 下仍需满足安全性；这和你现在必须保证 leaf (n) 安全是同一个原则。

### 第二层：更大的 split factor (k)

也就是：

[
k=2,\ 4,\ 8,\ldots
]

这对应多层 module decomposition：

[
R_N
\to
R_{N/2}^{\oplus 2}
\to
R_{N/4}^{\oplus 4}
\to
\cdots
\to
R_{N/k}^{\oplus k}.
]

这里可以写成递归版本：

[
F_{N,k}^{\mathrm{fac}}
======================

\Merge_{N,k}
\circ
\left(
\bigoplus_{r=0}^{k-1}
F_{n}
\right)
\circ
\Split_{N,k}.
]

如果你以后跑：

[
\log N=18,\quad k=4,\quad \log n=16,
]

这就是一个非常好的高维度安全版验证。

### 第三层：更一般的 circuit class

这才是理论上最有分量的一层。你可以说：

只要一个同态电路可以写成：

[
\text{linear transform}
\rightarrow
\text{coordinate-wise nonlinear map}
\rightarrow
\text{linear transform},
]

并且两个线性变换满足 split-compatible 条件，那么它就能用同样的思想分解。

CKKS bootstrapping 是这个框架的核心实例。

以后你可以讨论可能适用的其他结构，比如：

[
\text{homomorphic activation evaluation},
]

[
\text{functional bootstrapping-like maps},
]

[
\text{某些 DFT-domain nonlinear transforms}.
]

但这里要谨慎：不要直接声称都能用。你只需要说：

[
\boxed{
\text{This suggests a general criterion for subring factorization of linear--coordinatewise--linear homomorphic circuits.}
}
]

## 5. 我建议你最终这样组织理论部分

可以写成四个 theorem / proposition。

### Proposition 1: Split-compatible sandwich circuits

证明一般框架：

[
F_N
===

L_N^{(2)}\circ\Phi_N\circ L_N^{(1)}
]

在 split-compatible 条件下可分解为：

[
F_N
===

\Merge_k
\circ
\left(
\bigoplus_r
L_n^{(2)}\circ\Phi_n\circ L_n^{(1)}
\right)
\circ
\Split_k.
]

### Proposition 2: CKKS bootstrapping core satisfies the criterion

令：

[
L^{(1)}=\CtwoS,\quad
\Phi=\EvalMod,\quad
L^{(2)}=\StwoC.
]

证明 CKKS bootstrapping core 满足 Proposition 1 的条件。

### Proposition 3: Implementation-normalized version

考虑实现 scaling：

[
F_{N,k}^{\mathrm{fac,impl}}
\approx
\gamma_{\mathrm{impl}}F_N^{\mathrm{impl}},
]

其中：

[
\gamma_{\mathrm{impl}}
======================

\frac{
\CtwoSScaling_{\mathrm{leaf}}\cdot \StwoCScaling_{\mathrm{leaf}}
}{
\CtwoSScaling_{\mathrm{top}}\cdot \StwoCScaling_{\mathrm{top}}
}.
]

### Proposition 4: Complexity consequence

如果：

[
T_{\mathrm{core}}(d)
\approx
c d^p(\log d)^q,
]

则并行 leaf 版本的理想 speedup 为：

[
S
\approx
k^p
\left(
\frac{\log N}{\log(N/k)}
\right)^q,
]

再减去 Split/Merge/shared overhead。

## 6. 你现在可以放心按这个方向写

我觉得你这个想法是对的：先把本文的实际贡献写成 CKKS bootstrapping core 的分解，然后再抽象出一个 general criterion。这样主定理就不会显得只是“一个特殊实现技巧”。

最好的叙述是：

[
\boxed{
\text{本文首先提出一个 split-compatible sandwich-circuit criterion；然后证明 CKKS bootstrapping core 是该 criterion 的一个非平凡实例。}
}
]

这样“更高维度”的解释就自然了：

[
\boxed{
\text{不是只在某个 }N,k\text{ 上实验成立，而是在 ring/module decomposition 下有一个可递归、可参数化的分解结构。}
}
]

HERMES 仍然作为底层 ring switching / module view 的支撑，而你的新东西是把这个 module split-compatible 观点用于 CKKS bootstrapping core。HERMES 本身的任务是 ring packing，并且它的完整 HERMES 流程是 base ring packing、ring switching、HalfBTS 三步；你的任务则是对一个 CKKS bootstrapping core 做 Split–leaf core–Merge 分解，这个定位是清楚的。
