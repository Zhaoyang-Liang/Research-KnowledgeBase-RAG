`Coefficient Split Semantics` 不建议塞进普通 Preliminaries。

原因：

1. Preliminaries 应只放读者必须知道的既有背景，例如 CKKS、C2S/S2C、ring switching、module decomposition。
2. `coefficient split 不是 slot-preserving split`、`split 后不需要恢复 big-ring slots`、`no-B_k` 这些是本文核心理解，不是常识背景。
3. 如果放进 Preliminaries，贡献会被弱化成“背景定义”；如果放成独立技术章节，它自然引出主定理。

推荐结构：

```text

```

其中 Section 2 只介绍已有工具，Section 3 是本文自己的语义澄清，Section 4 是正式 theorem/proof。

### Section 3. Coefficient-Split Semantics

这是本文自己的语义章节。建议标题保留：

```text
Coefficient-Split Semantics
```

或者更强一点：

```text
Why Coefficient Split Suffices for CKKS Bootstrapping
```

建议小节：

#### 3.1 Split target at ciphertext-message level

核心句：

```text
Split_k(P)=(P_0,...,P_{k-1}) is a statement about the plaintext message represented by a ciphertext, not a public extraction of ciphertext components.
```

要写清：

- `P_r` 是消息 polynomial 的 coefficient residue component。
- ciphertext-level `RSDown` 目标是产生 leaf ciphertexts 表示 `P_r(Y)`。
- 这一步需要 ring switching / key switching。

#### 3.2 Coefficient split is not slot selection

先写 `k=2`：

```text
P(X)=A(X^2)+X B(X^2)
P(alpha)=A(theta)+alpha B(theta)
P(-alpha)=A(theta)-alpha B(theta)
```

因此：

```text
A(theta) = (P(alpha)+P(-alpha))/2
B(theta) = (P(alpha)-P(-alpha))/(2 alpha)
```

结论：

```text
coefficient split maps paired big-ring slots to local linear combinations, not to selected original slots.
```

再给一般 `k` fiber/Vandermonde 解释即可，不必写太长。

#### 3.3 Slot-preserving split requires an extra transform

讲 `Q^+=A+hB`, `Q^-=A-hB`。

这里引入 `B_k` 或 slot-lifting transform 的语义：

```text
B_k is a canonical-slot lifting/recovery transform. It is relevant if one wants leaf slots to preserve big-ring slot values.
```

#### 3.4 Why bootstrapping does not need slot preservation

这是本节最关键的论证。

核心句：

```text
CKKS bootstrapping does not apply EvalMod to the original canonical slots. It first applies C2S, so EvalMod acts on coefficient-packed slots.
```

因此：

```text
Split_k followed by leaf C2S_n gives exactly the residue-class coefficient sub-vectors of top C2S_N.
```

结论：

```text
The right object to preserve is not big-ring slots but C2S-output coefficient coordinates.
```

#### 3.5 Section summary

四句话即可：

1. split 是密文消息语义，不是公开抽系数；
2. coefficient split 不是 slot-preserving；
3. slot-preserving 需要额外 `B_k`/lifting transform；
4. CKKS core 只需要 coefficient-packed coordinates，所以 no-`B_k` 路线成立。

### Section 4. Core Factorization Theorem

这是主证明章节。材料来源主要是：

```text
03_证明系统/逐坐标证明.tex
```

建议不要把 `03` 的长解释全部搬进论文，而是抽成 theorem-proof 结构。

#### 4.1 Normalized model and notation

定义：

```text
Can_d       canonical-slot coordinate space
Coeff_d     coefficient-packed coordinate space
C2S_d: Can_d -> Coeff_d
S2C_d: Coeff_d -> Can_d
Pi_k: Coeff_N -> direct_sum_r Coeff_n
Split_k: Can_N -> direct_sum_r Can_n
Merge_k: direct_sum_r Can_n -> Can_N
```

语义约定：

```text
C2S_d(can_d(P)) = coeff_d(P)
S2C_d(coeff_d(P)) = can_d(P)
```

#### 4.2 Lemma 1: Split-C2S compatibility

Statement:

```text
(oplus_r C2S_n) o Split_k = Pi_k o C2S_N.
```

Proof skeleton:

1. Let `P(X)=sum_i a_i X^i`.
2. Let `p=coeff_N(P)`.
3. Split gives `P_r(Y)=sum_j a_{r+jk}Y^j`.
4. leaf `C2S_n` gives `coeff_n(P_r)=S_r p`.
5. top `C2S_N` gives `p`, then `Pi_k` gives `(S_0p,...,S_{k-1}p)`.
6. Both paths agree.

#### 4.3 Lemma 2: EvalMod coordinate-wise compatibility

Statement:

```text
If EvalMod_N=f^{oplus N} and EvalMod_n=f^{oplus n},
then (oplus_r EvalMod_n) o Pi_k = Pi_k o EvalMod_N.
```

Proof skeleton:

1. Let `x=(x_0,...,x_{N-1})`.
2. Left path coordinate `(r,j)` gives `f(x_{r+jk})`.
3. Right path coordinate `(r,j)` also gives `f(x_{r+jk})`.
4. No linearity of `f` is needed.

Important sentence:

```text
The nonlinearity of EvalMod is harmless; only coordinate independence is required.
```

#### 4.4 Lemma 3: S2C-Merge compatibility

Statement:

```text
Merge_k o (oplus_r S2C_n) o Pi_k = S2C_N.
```

Proof skeleton:

1. Let `y=(y_0,...,y_{N-1})`.
2. `Pi_k y` gives leaf vectors `S_r y`.
3. Interpret `S_r y` as coefficients of `Y_r(Y)=sum_j y_{r+jk}Y^j`.
4. Merge gives:

```text
sum_r X^r Y_r(X^k)
= sum_r sum_j y_{r+jk} X^{r+jk}
= sum_i y_i X^i.
```

5. This is exactly the polynomial whose canonical slots are `S2C_N(y)`.

#### 4.5 Main theorem

Statement:

```text
S2C_N o EvalMod_N o C2S_N
=
Merge_k o (oplus_r S2C_n o EvalMod_n o C2S_n) o Split_k.
```

Proof:

Use the three lemmas by composition.

Suggested final paragraph:

```text
This theorem does not say that coefficient split preserves big-ring canonical slots. It says that after C2S, the relevant coordinates are coefficient-packed coordinates, and those are exactly decomposed by Pi_k.
```

#### 4.6 Implementation convention note

短小一节，不要展开实验：

```text
In a concrete library, C2S/S2C may include fixed permutations and scaling conventions. These are absorbed into Pi_k and an implementation normalization factor. They are not part of the algebraic theorem.
```

这里可以预告 `gamma_impl`：

```text

```

## 5. 可直接进入 `初稿_v2.tex` 的核心 theorem 草案

### Lemma: Split-C2S compatibility

Let `N=kn`. Under the normalized layout convention,

```text
(oplus_{r=0}^{k-1} C2S_n) o Split_k = Pi_k o C2S_N.
```

Proof: choose `P(X)=sum_i a_i X^i`; after split, `P_r(Y)=sum_j a_{r+jk}Y^j`; leaf `C2S_n` outputs the coefficient vector `(a_r,a_{r+k},...)`; top `C2S_N` outputs `(a_0,...,a_{N-1})`, and `Pi_k` groups it into the same residue-class vectors.

### Lemma: EvalMod compatibility

If `EvalMod_N=f^{oplus N}` and `EvalMod_n=f^{oplus n}` for the same scalar function `f`, then

```text
(oplus_r EvalMod_n) o Pi_k = Pi_k o EvalMod_N.
```

Proof: both sides map coordinate `(r,j)` to `f(x_{r+jk})`.

### Lemma: S2C-Merge compatibility

Under the same layout convention,

```text
Merge_k o (oplus_r S2C_n) o Pi_k = S2C_N.
```

Proof: leaf vectors `S_r y` are interpreted as coefficients of `Y_r(Y)`; merge reconstructs `sum_r X^rY_r(X^k)=sum_i y_iX^i`; this is exactly the input interpreted by top `S2C_N`.

### Theorem: CKKS bootstrapping core factorization

Under the normalized layout convention and coordinate-wise EvalMod assumption,

```text
S2C_N o EvalMod_N o C2S_N
=
Merge_k o (oplus_r S2C_n o EvalMod_n o C2S_n) o Split_k.
```

This is an ideal algebraic statement. Ciphertext-level ring switching noise and implementation normalization are outside the algebraic theorem.
