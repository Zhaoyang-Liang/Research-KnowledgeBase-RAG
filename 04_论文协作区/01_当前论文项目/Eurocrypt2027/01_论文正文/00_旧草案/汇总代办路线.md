如果目标是 **Eurocrypt 级别**，我觉得你现在已经有一个不错的核心现象：

[
\boxed{
\text{用 HERMES-style Split/Merge，把大环 CKKS bootstrapping core 分解到子环 leaf 上，并且 no-}B_k\text{ 跑通。}
}
]

但现在还不够。Eurocrypt 通常不会只接受“实验快了”的故事，你需要把它包装成一个完整的理论 + 实现 + 安全 + 复杂度贡献。下面是我建议你补的东西，按重要性排序。

---

# 1. 必须补：清晰的主定理

你现在需要把核心 claim 写成一个 theorem，而不是实验观察。

建议主定理形式：

[
\boxed{
\widetilde{\BTS}_{N,k}^{\mathrm{fac}}
=====================================

\gamma_{\mathrm{impl}}^{-1}
\Merge_k
\circ
\left(
\bigoplus_{r=0}^{k-1}
\BTS_n^{(r)}
\right)
\circ
\Split_k
\approx
\BTS_N.
}
]

其中：

[
n=N/k.
]

然后分成两个版本。

## 理想数学版本

在理想线性变换和精确 EvalMod 下：

[
\boxed{
\BTS_{N,k}^{\mathrm{fac}}
=========================

\BTS_N.
}
]

这里 (\gamma=1)。

## 实现版本

在 Lattigo/HEaaN-style CKKS bootstrapping 实现中：

[
\boxed{
\BTS_{N,k}^{\mathrm{fac,impl}}
\approx
\gamma_{\mathrm{impl}}
\BTS_N^{\mathrm{impl}}.
}
]

其中：

[
\boxed{
\gamma_{\mathrm{impl}}
======================

\frac{
\CtwoSScaling_{\mathrm{leaf}}
\cdot
\StwoCScaling_{\mathrm{leaf}}
}{
\CtwoSScaling_{\mathrm{top}}
\cdot
\StwoCScaling_{\mathrm{top}}
}.
}
]

这个不是经验公式，而是实现中 C2S/S2C matrix scaling 的直接推导。你需要把它写成 lemma。

# 2. 必须补：正式正确性证明

你的证明现在有思路，但需要整理成论文式结构：

## Lemma 1：ring decomposition

[
R_{q,N}
\simeq
\bigoplus_{r=0}^{k-1}
R_{q,n}\cdot X_N^r.
]

HERMES 里就是这样看待 ring switching 的：当 (k\mid N) 时，大环 (R_{q,N}) 可以视为 (R_{q,N/k}) 上的 rank-(k) module，并定义 module decomposition map (\pi^k_{q,N})。

## Lemma 2：Split/Merge correctness

[
\Merge_k\circ\Split_k=\mathrm{Id}.
]

如果 secret 属于合适的子环，HERMES 也说明大环 ciphertext 可以 split 成 (k) 个小环 ciphertext，反向 Combine 可以恢复。并且在 coefficients-encoded CKKS 下，这个 bijection 是 direct sum，即 coefficient rearrangement，本身几乎没有计算成本。

## Lemma 3：C2S compatibility

证明：

[
\Split_k\circ \CtwoS_N
\approx
\left(
\bigoplus_r \CtwoS_n
\right)
\circ
\Split_k.
]

这里要说明 bit-reversal / leaf order / blocked layout 如何处理。

## Lemma 4：EvalMod coordinate-wise compatibility

因为 EvalMod 是逐坐标函数：

[
\EvalMod(z_0,\ldots,z_{s-1})
============================

(f(z_0),\ldots,f(z_{s-1})).
]

所以只要 C2S 后 layout 对齐，就有：

[
\Split_k\circ\EvalMod_N
=======================

\left(
\bigoplus_r \EvalMod_n
\right)
\circ\Split_k.
]

重点解释：**EvalMod 虽然非线性，但它是逐坐标非线性，所以可以穿过 Split 的坐标重排。**

## Lemma 5：S2C/Merge compatibility

证明：

[
\Merge_k
\circ
\left(
\bigoplus_r \StwoC_n
\right)
\approx
\StwoC_N.
]

实现中加：

[
\gamma_{\mathrm{impl}}.
]

最后得到主定理。

# 3. 必须补：安全分析

这是 Eurocrypt 最容易卡你的地方。

你必须非常清楚地写：

[
\boxed{
\text{leaf security 不继承 top security。}
}
]

因为 leaf 真正在：

[
R_{QP,n}
]

上暴露 bootstrapping keys / rotation keys / switching keys，所以安全性要看：

[
\boxed{
(n,\log(QP),\chi_s,\sigma).
}
]

不能只看 top：

[
(N,\log(QP)).
]

你应该给出一张安全参数表：

|           case | top (\log N) | (k) | leaf (\log n) |    (\log(QP)) | claimed status               |
| -------------: | -----------: | --: | ------------: | ------------: | ---------------------------- |
|      prototype |           16 |   4 |            14 | (\approx1520) | correctness/performance only |
|      prototype |           16 |   2 |            15 | (\approx1520) | not final security           |
| security-aware |           17 |   2 |            16 | (\approx1520) | main secure candidate        |
|         future |           18 |   4 |            16 | (\approx1520) | full (k=4) secure candidate  |

还要明确 secret distribution：

[
s_i\leftarrow{-1,0,1}
]

是 dense uniform ternary，还是 sparse ternary with Hamming weight (h)。

如果用 sparse secret，必须额外分析 sparse-secret attacks / estimator setting。否则建议先用 dense ternary 做主安全 claim。

你还需要用 lattice estimator 或 HE standard 参数表给 bit security，不要只说“常见安全”。

# 4. 必须补：理论噪声界与失败概率

不能只给实验 error。需要写出理论形式：

[
\Pr[\mathrm{fail}*{\mathrm{fac}}]
\le
k\Pr[|I*{\mathrm{leaf}}|*\infty>K*{\mathrm{leaf}}]
+
M_{\mathrm{KS}}\delta_{\mathrm{KS}}
+
\delta_{\mathrm{round}}
+
\delta_{\mathrm{precision}}.
]

这里失败至少分两类：

## EvalMod range failure

[
\Pr[|I|_\infty>K].
]

Subring secret 相关论文也会把 bootstrapping failure probability 写成这种形式：

[
\kappa=\Pr[|I|_\infty>K].
]

你需要说明 factored 后有 (k) 个 leaves，所以用 union bound：

[
\delta_{\mathrm{range,fac}}
\le
k\delta_{\mathrm{range,leaf}}.
]

## precision failure

最终：

[
|\Dec(\ct_{\mathrm{out}})-m|_\infty

>

\varepsilon_{\mathrm{target}}.
]

你可以给保守递推：

[
B_{\mathrm{fac}}
\le
|\gamma_{\mathrm{impl}}|^{-1}
\left(
L_{\Merge}
\left[
L_{\StwoC}
\left(
L_{\Eval}
L_{\CtwoS}(B_0+B_{\Split})
+
L_{\Eval}B_{\CtwoS,\mathrm{arith}}
+
\epsilon_{\mathrm{poly}}
+
B_{\Eval,\mathrm{arith}}
\right)
+
B_{\StwoC,\mathrm{arith}}
\right]
+
B_{\Merge}
\right).
]

不用一定给非常紧的数值，但要有理论框架。

# 5. 必须补：复杂度与开销分解

现在你已经有总时间，但 Eurocrypt 需要知道快在哪里。

建议写成：

[
T_{\mathrm{dir}}(N)
===================

T_{\mathrm{shared}}(N)
+
T_{\mathrm{core}}(N),
]

其中：

[
T_{\mathrm{shared}}(N)
======================

T_{\ScaleDown}(N)+T_{\ModUp}(N),
]

[
T_{\mathrm{core}}(N)
====================

T_{\CtwoS}(N)+T_{\EvalMod}(N)+T_{\StwoC}(N).
]

Factored：

[
T_{\mathrm{fac}}(N,k)
=====================

T_{\mathrm{shared}}(N)
+
T_{\Split}(N,k)
+
T_{\Merge}(N,k)
+
\frac{k}{\min(k,w)\eta_{\mathrm{par}}}
T_{\mathrm{core}}(N/k)
+
T_{\mathrm{sync}}.
]

HERMES 给你 Split/Merge 的底层成本模型。它把 key switching 拆成：

[
\mathrm{ModUp}
+
\mathrm{MultSwk}
+
\mathrm{ModDown}.
]

论文中明确说 ModUp/ModDown 是 (O(N\log N))，Hadamard multiplication 是 (O(N))，switching key size 是 (2N\log(qp))。

所以你可以推：

[
T_{\Split}^{\mathrm{KS}}(N,k)
\approx
\sum_{j=0}^{\log_2 k-1}
2^j
\mathsf{KS}(N/2^j,Q,P).
]

如果：

[
\mathsf{KS}(d,Q,P)=O((L_Q+L_P)d\log d),
]

则：

[
T_{\Split}^{\mathrm{KS}}(N,k)
=============================

O\left(
(L_Q+L_P)
N
\left[
\ell\log N-\frac{\ell(\ell-1)}{2}
\right]
\right),
]

其中：

[
\ell=\log_2 k.
]

Merge 同理。

# 6. 必须补：stage timing，而不是只给 total timing

你现在总时间很好：

[
\log N=17,k=2:
\quad
117.21s\rightarrow23.30s,
\quad
5.03\times.
]

但还不够。你需要加一张 stage timing 表：

| stage     | direct (\log N=17) | factored (\log N=17,k=2) |
| --------- | -----------------: | -----------------------: |
| ScaleDown |                    |                          |
| ModUp     |                    |                          |
| Split     |                  — |                          |
| C2S       |                    |     leaf wall / leaf sum |
| EvalMod   |                    |     leaf wall / leaf sum |
| S2C       |                    |     leaf wall / leaf sum |
| Merge     |                  — |                          |
| Total     |                    |                          |

最重要的是同时报告：

[
\text{leaf wall time}

和：

[
\text{leaf CPU-sum time}.

这样你能区分：

[
\text{算法降维收益}

]

否则 reviewer 会问：

你要回答：

> No. The speedup exceeds (k) because large-ring bootstrapping has superlinear scaling and worse memory locality.

# 7. 必须补：key size 和 memory

HERMES 特别重视 key size。它报告 HERMES0/HERMES1 的 latency 和 total key sizes，并区分 ring packing keys 和 BTS keys。

你的 paper 也必须有：

| case                     |  BTS key size | Split/Merge key size | total eval key size | peak memory |
| ------------------------ | ------------: | -------------------: | ------------------: | ----------: |
| direct (\log N=17)       |               |                    — |                     |             |
| factored (\log N=17,k=2) | leaf BTS keys |  ring switching keys |                     |             |

并且要说明 leaf keys 是共享还是每个 leaf 独立：

[
\mathrm{KeySize}_{\mathrm{fac}}
===============================

|\mathrm{SplitMergeKeys}_{N,k}|
+
\eta|\mathrm{BTSKeys}_n|.
]

其中：

[
\eta=
\begin{cases}
1,& \text{shared leaf keys},\
k,& \text{independent leaf keys}.
\end{cases}
]

这个如果不写清楚，会被 reviewer 抓。

# 8. 必须补：和 HERMES 的关系与区别

你要非常小心定位贡献。

不要写：

> We propose Split/Merge or ring switching.

因为 HERMES 和 GHPS 已经有 ring switching。

应该写：

[
\boxed{
\text{We use HERMES-style ring switching as the backend.}
}
]

你的贡献是：

[
\boxed{
\text{We identify a no-}B_k\text{ factorization of the CKKS bootstrapping core over subrings.}
}
]

区别：

| HERMES                                              | 你的工作                                                                  |
| --------------------------------------------------- | --------------------------------------------------------------------- |
| many LWE/MLWE ciphertexts (\to) one RLWE ciphertext | one CKKS ciphertext (\to) split leaf BTS (\to) merged CKKS ciphertext |
| ring packing / transciphering                       | bootstrapping core factorization                                      |
| base ring packing + ring switching + HalfBTS        | Split + leaf full BTS core + Merge                                    |
| focuses on key-size/time of ring packing            | focuses on reducing large-ring C2S/EvalMod/S2C cost                   |

HERMES 说它先 base-ring-pack 到小 degree RLWE，再 ring switch 合成 high-degree RLWE，最后 HalfBTS。

你的流程不是这个，而是在 bootstrapping 内部拆 core。

# 9. 必须补：对比基线

你需要至少三种 baseline。

## Baseline A：same top (N)

主实验：

[
\text{Direct BTS at } \log N=17
\quad
\text{vs}
\quad
\text{Factored } \log N=17,k=2.

这是算法公平。

## Baseline B：throughput-normalized

因为 (\log N=17) 的 slots 是 (\log N=16) 的两倍，所以需要比较：

[
T_{\mathrm{fac}}(2^{17},k=2)
\quad
\text{vs}
\quad
2T_{\mathrm{dir}}(2^{16}).
]

这对 ML/batch inference 叙事重要。

## Baseline C：parallel-only control

你要证明不是单纯多线程导致：

[
\text{Direct } \log N=17 \text{ with same number of threads}
]

vs

[
\text{Factored } \log N=17,k=2 \text{ with two leaf workers}.
]

如果 direct 也能多线程，那么要把线程数控制公平。

# 12. 建议补：limitations section

Eurocrypt reviewer 会喜欢诚实的 limitations。

你可以写：

1. 当前不声称 leaf security 继承 top security；
2. 安全参数必须基于 leaf (n) 重新估；
3. EvalMod failure probability 需要单独预算；
4. normalization factor 是 implementation-dependent；
5. Split/Merge key material 可能抵消部分收益；
6. (k) 过大时 leaf security 和 Split/Merge overhead 会成为瓶颈；
7. (\log N=18,k=4) 是未来更完整的安全版实验。

# 14. 我对“能不能发 Eurocrypt”的判断

现在的状态我会这样评价：

[
\boxed{
\text{作为 preprint / workshop / internal report 已经很有价值。}
}
]

但如果要冲 Eurocrypt，当前还缺：

[
\boxed{
\text{严格 theorem + 安全估计 + 失败概率 + key/memory overhead + 稳定实验。}
}
]

最有潜力的主线是：

> We show that CKKS bootstrapping admits a no-(B_k) subring factorization: after a HERMES-style split, the C2S–EvalMod–S2C core can be evaluated independently over secure subrings and merged back, preserving correctness up to an implementation-determined scaling factor. This reduces the dominant large-ring bootstrapping core and yields a (5.03\times) one-shot speedup at ((\log N,k,\log n)=(17,2,16)), while maintaining a security-aware leaf dimension.

这个故事是有潜力的。
但 Eurocrypt 版本必须把它从“实验发现”升级成“可证明、可参数化、可复现的算法”。
