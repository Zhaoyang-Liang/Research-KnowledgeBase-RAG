这些日志结果**很好，而且比上一版更干净**。核心结论是：

[
\boxed{
\text{纯 no-}B_k\text{ 版本跑通了；direct full bootstrapping 与 factored full bootstrapping 在除以 }k\text{ 后高度一致。}
}
]

而且最重要的新发现是：

[
\boxed{
\text{去掉 }B_k\text{ 相关 level reservation 后，direct 和 factored 输出 Level 都是 }10。
}
]

这说明之前看到的 `direct/factored = 10/8` 的 2-level penalty **不是 no-(B_k) 分解本身必然造成的**，而大概率来自之前程序里给 (B_k/B_k^{-1}) 预留 level 的实现配置。

## 3. 最重要的改进：Level penalty 消失了

这次日志里：

[
\text{Direct output Level}=10,
\qquad
\text{Factored output Level}=10.
]

这在 (k=2) 和 (k=4) 两组都成立。 

这非常重要。它说明：

[
\boxed{
\text{no-}B_k\text{ 分解本身不必然带来 2-level penalty。}
}
]

上一版看到的 Level (10/8)，现在基本可以解释为：leaf bootstrapping 参数里人为给 (B_k/B_k^{-1}) 预留了两层，而不是 no-(B_k) 路线天然损失两层。

这会显著增强你的结果，因为现在可以说：

[
\boxed{
\text{当前纯 no-}B_k\text{ 实现同时保持 correctness、保持输出 level，并获得加速。}
}
]

## 4. C2S 与 EvalMod 交换图验证得很漂亮

两组实验都显示：

[
(\oplus_r \mathrm{C2S}_n)\circ \mathrm{Split}
]

和

[
S\circ \mathrm{C2S}_N
]

在 blocked layout 下对齐到 (10^{-11}) 左右。

(k=2)：

[
1.45\times 10^{-11}.
]

(k=4)：

[
9.17\times 10^{-12}.
]

这说明线性交换图基本是机器精度级别成立。 

EvalMod 后误差变大到：

[
10^{-6}\sim 10^{-5}
]

量级，这是合理的，因为 EvalMod 是近似多项式计算，会引入近似误差和同态噪声。关键是它仍然很小，并且最后 S2C+Merge 后 direct/factored div-(k) 仍然保持 (10^{-7}) 量级。

## 5. (\gamma_k=k) 现在证据更强

两组日志都清楚显示：

[
\mathrm{Factored}_{raw}
]

不是错，而是整体大了 (k) 倍。

(k=2) 时 raw 输出约为 plaintext 的 2 倍，除以 2 后误差降到 (7.19\times10^{-8})。

(k=4) 时 raw 输出约为 plaintext 的 4 倍，除以 4 后误差降到 (1.08\times10^{-7})。

所以现在可以更有把握地写：

[
\boxed{
\gamma_k=k.
}
]

至少在当前 Lattigo RingPacking/S2C/Merge convention 下，实验强烈支持这个结论。

## 6. Bootstrapping 效果本身也没有变差很多

对 (k=4)：

direct full bootstrapping 对 plaintext 的最大误差是：

factored div-(k) 对 plaintext 的最大误差是：

[

factored 大概比 direct 差 3 倍左右，但仍然在 (10^{-7}) 量级。这非常可接受。

对 (k=2)：

direct 是：

[
2.84\times 10^{-8},
]

factored div-(k) 是：

[
7.19\times10^{-8}.
]

也是同一量级。

所以可以说：

[
\boxed{
\text{factored no-}B_k\text{ full bootstrapping 的精度与 direct bootstrapping 同量级。}
}
]

## 7. 加速结果：成立，但比上一版低一些

这次 (k=4) full speedup 是：

[
14.36/5.76 \approx 2.49\times.
]

之前你的表格里曾有 (3.09\times)。这次下降可能来自几个原因：

1. 新代码记录更完整，可能结构稍重；
2. reps、warmup、机器状态不同；
3. leaf evaluator pool、GC、并行调度会影响；
4. direct/factored benchmark 的函数路径和上一版不完全一样；
5. 这次确实是更“干净”的 no-(B_k) full pipeline，应该优先相信这版。

但即使按这版结果：

[
\boxed{
k=4\text{ 时 full speedup }=2.49\times
}
]

仍然是很好的结果。并行效率约：

[
2.49/4\approx 62.3%.
]

(k=2) 时 speedup 是：

[
1.83\times,
]

并行效率约：

[
1.83/2\approx 91.5%.
]

这也合理：(k=4) 时 Split/Merge、内存、调度、leaf key/evaluator overhead 更明显。

## 9. 最终判断

现在的结论可以比之前更强：

[
\boxed{
\text{程序结果正确，且强力支持 no-}B_k\text{ CKKS full bootstrapping decomposition。}
}
]

更具体地说：

[
\boxed{
\frac{1}{k}
\mathrm{Merge}*k
\circ
\left(
\bigoplus*{r=0}^{k-1}
\mathrm{BTS}_{N/k}
\right)
\circ
\mathrm{Split}_k
\approx
\mathrm{BTS}_N
}
]

在当前实验中：

* (k=2,\log N=13) 成立；
* (k=4,\log N=16) 成立；
* (\gamma_k=k)；
* direct/factored 输出 level 相同；
* factored div-(k) 的 bootstrapping 误差与 direct 同量级；
* full pipeline 有实际加速。

最值得强调的新结论是：

[
\boxed{
\text{纯 no-}B_k\text{ 实现没有观察到 level penalty。}
}
]

这比之前的结果更漂亮。
