  这个结果很好，说明**第一层代数/RNS 交换性已经过了**：

[
Split_k\circ \mathrm{ModUp}_N
=============================

(\oplus \mathrm{ModUp}_n)\circ Split_k
]

以及 drop primes、basis conversion、rounding-scale 这些逐系数 RNS 操作，至少在纯 coefficient/RNS 模型里都和 coefficient/module split 交换。

但这一步还没有包含 **Lattigo 的 RingPacking key switching 噪声**。所以下一步应该验证更接近真实路径的这个等式：

[
Split\bigl(ModUp_N(ScaleDown_N(ct))\bigr)
\quad ?\approx \quad
(\oplus ModUp_n)\bigl(Split(ScaleDown_N(ct))\bigr).
]

也就是：

### Path A

[
ScaleDown_N
\to
ModUp_N
\to
RingSwitchDown/Split
]

### Path B

[
ScaleDown_N
\to
RingSwitchDown/Split
\to
ModUp_n
]

它会比较：

[
A_i = Split_i(ModUp_N(ScaleDown(ct)))
]

和

[
B_i = ModUp_n(Split_i(ScaleDown(ct)))
]

并打印每个 leaf 的 raw error、fitted-gamma error，以及 merge 回 top 后与 top ModUp 的误差。

这个实验的意义是：

[
\boxed{
\text{验证能否把 top ModUp 移到 RingSwitchDown 之后，在 leaf 上各自 ModUp。}
}
]

如果这个也过了，那么 RNS-aware 方向就有了第二层证据：不仅纯 RNS 层可交换，而且 Lattigo ciphertext-level 的 ring switching 调度也基本可行。

接下来第三步才是 reduced-(Q_{\text{leaf}})：在 Path B 里让 leaf evaluator 使用更短的 (Q_{\text{leaf}}) / (P_{\text{leaf}})，然后看 leaf bootstrapping correctness 是否还能保持。
