# top17-leaf16 split bootstrapping 参数选取办法

本文档记录这次 top17->leaf16 成功参数的选取逻辑。

## 1. 目标

目标是构造：

```text
top logN = 17
split layers = 1
leaf logN = 16
leaf BTS = Lattigo 自带 CKKS bootstrapping
security accounting = PQ / logQP
baseline = 不跑
```

和 top16->leaf15 的低输出 level 点不同，这里 leaf16 的安全窗口更大，因此可以保留较高输出 level。

## 2. PQ 由哪些部分组成

本实验里的总 `logQP` 不是只由输出 ciphertext 的 Q 组成，而是：

```text
logQP = residual/output Q + bootstrapping internal Q + P
```

这次使用：

```text
q0Bits = 45
circuitLevels = 15
circuitPrimeBits = 35
numP = 5
defaultScale = 35
```

所以 residual/output Q 约为：

```text
45 + 15 * 35 = 570 bits
```

Lattigo default bootstrapping schedule 的 internal Q budget 约为：

```text
StC     = 3 * 39 = 117 bits
EvalMod = 8 * 60 = 480 bits
CtS     = 4 * 56 = 224 bits
--------------------------------
internal total = 821 bits
```

P 为：

```text
5 * 61 = 305 bits
```

总计：

```text
570 + 821 + 305 = 1696 bits
```

Go 侧 dry-run 实际打印：

```text
top/leaf logQ  = 1391.0
top/leaf logQP = 1696.0
```

其中：

```text
1391 = 570 residual/output Q + 821 internal Q
1696 = 1391 + 305 P
```

## 3. 为什么 top17->leaf16 可以保留 level 15

leaf16 的安全窗口比 leaf15 大很多。

当前程序 dry-run 的参考表给出：

```text
leaf logN=16, logQP <= 1747
```

本候选：

```text
leaf logQP = 1696
margin = 51 bits
```

再用本地 estimator 按 PQ 口径确认：

```bash
PATH="/opt/anaconda3/envs/sage/bin:$PATH" \
/opt/anaconda3/envs/sage/bin/python /Users/mac/opt/lattice-estimator/fhe_estimate.py \
  --n 65535 \
  --logQP 1696 \
  --sigma 3.2 \
  --tag leaf16_top17_split_lattigo_Lout15_QP1696 \
  --attacks primal_usvp,primal_bdd,dual_hybrid
```

结果：

```text
minimum estimated bits = 132.09138343060562
```

因此这个点满足 128-bit，并且输出 level 可以保持为 15。

## 4. 和 top16->leaf15 的区别

top16->leaf15 的困难在于 leaf15 的 PQ 安全窗口只有约 868 bits。Lattigo default schedule 单是：

```text
internal Q 821 + one P 61 = 882 bits
```

就已经超过 leaf15 安全窗口，所以必须换成更紧的 N15-style bootstrapping schedule，并牺牲输出 level。

top17->leaf16 不一样：

```text
leaf16 logQP bound ≈ 1747
default schedule with Lout=15 gives logQP=1696
```

所以它可以直接使用 default Lattigo bootstrapping schedule，不需要新增 preset。

## 5. 正确快速选参流程

以后选 top17->leaf16 参数，可以按下面流程：

```text
1. 固定 leaf logN=16。
2. 先决定目标输出 level Lout。
3. 估算 residual/output Q = q0Bits + Lout * circuitPrimeBits。
4. 加上 Lattigo default internal Q，约 821 bits。
5. 加上 P，当前稳定点为 numP=5，即约 305 bits。
6. 检查总 logQP 是否低于 leaf16 安全窗口。
7. 用 /Users/mac/opt/lattice-estimator/fhe_estimate.py 按 PQ 口径确认。
8. dry-run 检查 top/leaf Q/P basis 完全一致。
9. 只跑 split route，检查输出 level、precision、time。
```

本次具体代入：

```text
Lout = 15
q0Bits = 45
circuitPrimeBits = 35
numP = 5

logQP = 45 + 15*35 + 821 + 5*61 = 1696
```

## 6. 如果以后需要更高安全裕度

优先降低输出 level，而不是先盲目改 EvalMod 或消息生成代码：

```text
Lout=15 -> logQP≈1696
Lout=14 -> logQP≈1661
Lout=13 -> logQP≈1626
```

每少一个 35-bit 输出 level，PQ 直接下降约 35 bits，安全裕度会明显增加。

只有在 Lattigo schedule 本身不稳定或 key switching 不够时，才考虑调整 `numP`、internal schedule 或 scale。所有候选都必须重新跑 estimator，并以 PQ/logQP 为准。

```bash

  -logN=17 \
  -layers=1 \
  -run=ours \
  -leafEngine=lattigo \
  -q0Bits=45 \

  -leafWorkers=2 \
  -reps=1 \

```

