# top17-leaf15 split bootstrapping 参数选取办法

本文档记录 top17->leaf15 成功参数的选取逻辑。

## 1. 目标

目标是构造：

```text
top logN = 17
split layers = 2
leaf logN = 15
leaves = 4
leaf BTS = Lattigo 自带 CKKS bootstrapping
security accounting = PQ / logQP
baseline = 不跑
```

用户设定是：既然最终拆到 leaf15，那么 PQ 就按 leaf15 的安全窗口选择。因此这里直接复用 top16->leaf15 已经成功的 `n15qp849` 参数。

## 2. 为什么输出 level 仍然是 3

`n15qp849` 的 residual Q 是：

```text
Residual Q = [40, 31, 31, 31]
```

其中第一个 40-bit prime 是初始/特殊 residual prime，后面 3 个 31-bit prime 是 bootstrapping 后能保留下来的 computation levels。

因此：

```text
output level = 3
output circuit moduli = [31, 31, 31]
```

这和 top ring 是 `logN=16` 还是 `logN=17` 无关。只要 leaf BTS 使用同一套 leaf15 `n15qp849` schedule，输出 level 就仍然是 3。

## 3. PQ 口径

本实验必须看 leaf15 的 `logQP`：

```text
leaf logQP = 849
```

dry-run：

```text
top:  logN=17 qCount=15 pCount=2 logQ=737.0 logQP=849.0
leaf: logN=15 qCount=15 pCount=2 logQ=737.0 logQP=849.0
leaf logQP <= 868, margin=19.0 bits [PASS]
```

Estimator：

```bash
PATH="/opt/anaconda3/envs/sage/bin:$PATH" \
/opt/anaconda3/envs/sage/bin/python /Users/mac/opt/lattice-estimator/fhe_estimate.py \
  --n 32767 \
  --logQP 849 \
  --sigma 3.2 \
  --tag leaf15_top17_split_lattigo_n15qp849 \
  --attacks primal_usvp,primal_bdd,dual_hybrid
```

结果：

```text
minimum estimated bits = 130.89845721434037
```

所以该点满足 leaf15 PQ 口径下的 128-bit。

## 4. 为什么不使用 top17->leaf16 的参数

top17->leaf16 的成功参数是：

```text
logQP = 1696
output level = 15
```

它依赖 leaf16 的大安全窗口：

```text
leaf16 logQP bound ≈ 1747
```

但 top17->leaf15 的 leaf 安全窗口只有约：

```text
leaf15 logQP bound ≈ 868
```

因此不能把 top17->leaf16 的 full-ish 参数直接拿来给 leaf15 用。正确做法是按 leaf15 的 `n15qp849` 参数选择：

```text
logQP = 849
output level = 3
```

## 5. 正确快速选参流程

以后做 top17->leaf15 时：

```text
1. 固定 leaf logN=15。
2. 使用 n15qp849，而不是 Lattigo default schedule。
3. 设置 layers=2，使 top17 拆到 leaf15。
4. dry-run 检查 top/leaf exact same Q/P basis。
5. 用 estimator 检查 leaf15 logQP=849 的 PQ 安全性。
6. 只跑 split route，不跑 baseline。
```

本次命令：

```bash
go run . \
  -logN=17 \
  -layers=2 \
  -run=ours \
  -leafEngine=lattigo \
  -lattigoPreset=n15qp849 \
  -splitFirstLeafPreprocess=true \
  -parallelLeaves=true \
  -leafWorkers=4 \
  -reps=1 \
  -outputTSV=results/split_top17_leaf15_lattigo_n15qp849.tsv
```

## 6. 本次结果

```text
top logN = 17
leaf logN = 15
layers = 2
leaves = 4
logQP = 849.002817
output level = 3
total time = 12.318991750 s
output vs input L1 precision ≈ 16.19 bits
minimum estimated security ≈ 130.90 bits
```

这个实验说明：同一个 leaf15 低输出参数不仅能支持 top16->leaf15，也能支持 top17->leaf15。代价是 leaf 数变为 4，时间相应增加；好处是 PQ 仍然落在 leaf15 的安全窗口内。
