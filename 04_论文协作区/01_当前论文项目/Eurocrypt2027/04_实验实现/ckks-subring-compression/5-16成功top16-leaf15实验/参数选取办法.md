# top16-leaf15 split bootstrapping 参数选取办法

本文档记录这次成功参数的选取逻辑，并说明之前为什么一直选不出来。

## 1. 目标

目标不是构造 full-output-level top bootstrapping，而是构造：

```text
top logN = 16
split layers = 1
leaf logN = 15
leaf BTS = Lattigo 自带 CKKS bootstrapping
security accounting = PQ / logQP
output level 可以降低
```

因此 leaf bootstrapping 必须满足：

```text
leaf logQP <= leaf15 security bound
```

本地 estimator 给出的经验阈值是：

```text
leaf logN=15, n=32767, logQP≈868 -> about 128-bit
```

所以参数选择的硬约束是：

```text
leaf logQP <= 868
```

## 2. 之前的错误方法

之前主要沿着这个方向调：

```text
top logN=16
Lattigo default ordinary bootstrapping schedule
调 q0Bits / defaultScale / circuitPrimeBits / circuitLevels
```

这个方法的问题是：它默认使用的是 top16 ordinary bootstrapping 的内部参数，而不是适合 leaf15 的 bootstrapping 参数。

Lattigo default ordinary bootstrapping 的内部 Q budget 约为：

```text
StC     = 3 × 39 = 117 bits
EvalMod = 8 × 60 = 480 bits
CtS     = 4 × 56 = 224 bits
--------------------------------
internal total = 821 bits
```

如果还要用至少一个 P prime：

```text
P = 61 bits
```

那么即使不算 residual q0 和输出 levels，仅内部预算加 P 就是：

```text
821 + 61 = 882 bits
```

这已经超过 leaf15 的 868-bit 安全窗口。

所以在这个错误路径下，继续降低 `q0Bits`、`defaultScale`、`circuitPrimeBits` 只能做局部修补，无法根本解决问题。

## 3. 11-bit 精度误判

之前看到一些实验只有约 11-bit precision，容易误判为：

```text
leaf15 bootstrapping 精度不够
```

但实际原因是那些实验的输入 ciphertext 本身精度就低，例如：

```text
defaultScale = 25
q0Bits = 34
input precision ≈ 12 bits
output precision ≈ 11.5 bits
```

这不能说明 bootstrapping 失败，只能说明输入消息/scale 设置给出的原始精度低。

正确判断方法是：

```text
先看 input ciphertext vs plaintext 的 precision
再看 bootstrapped ciphertext vs input ciphertext 的 precision
```

如果输入本身只有 12 bits，那么输出 11 bits 是正常的。

## 4. 正确方法

正确方法是先在 leaf ring 上找一个能跑通且安全的 Lattigo direct bootstrapping 参数，再把它提升到 top16 split 实验里作为 leaf engine 的参数模板。

流程如下。

### Step 1: 从 leaf15 direct BTS 开始

先完全抛开 split，只验证：

```text
logN = 15
direct Lattigo CKKS bootstrapping
```

Lattigo 自带 N15 preset 大致为：

```text
Residual Q = [40, 31, 31, 31, 31]
P          = [56, 56]
StC        = [30, 30]
EvalMod    = 8 × 55
CtS        = [52, 52]
scale      = 2^31
```

该点：

```text
logQP = 880
output level = 4
```

功能上可行，精度正常，但 PQ 安全估计约：

```text
126.11 bits
```

略低于 128-bit。

### Step 2: 牺牲一个输出 level

减少一个 residual circuit prime：

```text
Residual Q = [40, 31, 31, 31]
```

其余 bootstrapping 内部参数不变：

```text
P          = [56, 56]
StC        = [30, 30]
EvalMod    = 8 × 55
CtS        = [52, 52]
scale      = 2^31
```

得到：

```text
logQ  ≈ 737
logQP ≈ 849
output level = 3
```

用 estimator 验证：

```bash
PATH="/opt/anaconda3/envs/sage/bin:$PATH" \
/opt/anaconda3/envs/sage/bin/python /Users/mac/opt/lattice-estimator/fhe_estimate.py \
  --n 32767 \
  --logQP 849 \
  --sigma 3.2 \
  --tag logN15_direct_bts_QP849_Lout3 \
  --attacks primal_usvp,primal_bdd,dual_hybrid
```

结果：

```text
minimum estimated bits = 130.90
```

因此该 leaf15 参数满足 PQ 口径 128-bit。

### Step 3: 将 leaf15 参数移植到 top16 split 实验

top16 split 实验需要 top 和 leaf 使用一致的 Q/P basis，否则 ring switching / merge 不方便对齐。

因此构造 top16 参数时，不再用 top16 default ordinary schedule，而是使用同一套 N15-style low-output schedule：

```text
lattigoPreset = n15qp849
top logN = 16
leaf logN = 15
top/leaf exact same Q/P basis
```

Dry run 应看到：

```text
top:  logN=16 qCount=15 pCount=2 logQ=737.0 logQP=849.0
leaf: logN=15 qCount=15 pCount=2 logQ=737.0 logQP=849.0
leaf logQP <= 868 [PASS]
```

### Step 4: 只跑 split route

当前阶段不需要跑 baseline。命令：

```bash
go run . \
  -logN=16 \
  -layers=1 \
  -run=ours \
  -leafEngine=lattigo \
  -lattigoPreset=n15qp849 \
  -splitFirstLeafPreprocess=true \
  -parallelLeaves=true \
  -leafWorkers=2 \
  -reps=1 \
  -outputTSV=results/split_top16_leaf15_lattigo_n15qp849.tsv
```

成功结果：

```text
top logQP = 849.000442
leaf logQP = 849.000442
output level = 3
output circuit moduli = [31 31 31]
total time = 5.119727667 s
input precision ≈ 18.08 bits
output vs input precision ≈ 17.13 bits
```

## 5. 快速选参规则

以后选 top16-leaf15 split 参数时，不要从 top16 default schedule 开始硬压。

推荐快速流程：

```text
1. 固定 leaf logN=15。
2. 先找 leaf15 direct BTS preset。
3. 用 estimator 检查 leaf logQP 是否 <= 868。
4. 如果略超，优先减少输出 residual levels。
5. 确认 direct leaf15 BTS 功能和精度正常。
6. 将该 leaf schedule 提升到 top16 split 实验中。
7. 保证 top/leaf 使用 exact same Q/P basis。
8. 只跑 split route 验证 correctness、precision、time。
```

## 6. 判断一个候选是否值得跑

先 dry run：

```bash
go run . \
  -dryRunParams=true \
  -logN=16 \
  -layers=1 \
  -run=ours \
  -leafEngine=lattigo \
  -lattigoPreset=n15qp849 \
  -splitFirstLeafPreprocess=true
```

只有满足以下条件才值得跑完整实验：

```text
leaf logQP <= 868
top/leaf Q/P basis exact match
output level >= 目标最低值
scale/q0 能给出足够 input precision
```

完整实验后，检查：

```text
input ciphertext precision
bootstrapped output vs input precision
output level
stage timing
```

不要只看最终 precision。如果输入 precision 本来很低，输出 precision 低不是 bootstrapping 参数失败。
