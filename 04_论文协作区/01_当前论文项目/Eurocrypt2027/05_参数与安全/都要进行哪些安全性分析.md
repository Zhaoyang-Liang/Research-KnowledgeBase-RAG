对，**安全性必须单独分析**。现在我们证明/探索的是：

[
\text{correctness / functional equivalence}
]

也就是：

[
\Merge\circ(\oplus \BTS_n)\circ\Split
\approx
\gamma_k \BTS_N.
]

这只说明“算出来的明文结果对不对”，**不等于密码学安全**。

更准确地说，你现在的理论成果回答的是：

> 大环 bootstrapping core 是否能在明文语义上分解成多个小环 bootstrapping core？

但还没有回答：

> 这个分解过程中引入的小环密文、ring-switching keys、leaf bootstrapping keys 是否仍然满足足够的 RLWE 安全性？

这两件事必须分开。

---

# 1. 为什么安全性可能有问题？

主要原因是：你把一个大环问题拆到了更小的环上。

原来安全性基于大环：

[
R_N=\mathbb{Z}_q[X]/(X^N+1)
]

现在 leaf 上用了小环：

[
R_n=\mathbb{Z}_q[Y]/(Y^n+1),
\qquad n=N/k.
]

RLWE 安全性强烈依赖维度 (n)、总模数大小 (Q)、误差分布、secret 分布等参数。小环维度更低，在同样模数 (Q) 下，安全性通常会下降。RLWE 本身是基于格问题的安全假设，其实际安全依赖精确参数选择，并且需要防范 subfield / algebraic attacks 等问题。([Emergent Mind][1])

所以，最核心的安全问题是：

[
\boxed{
leaf ring 的 RLWE 参数是否仍然达到目标安全级别？
}
]

比如你原来大环 (N=2^{16}) 安全，但拆成 (n=2^{15}) 后，如果仍然使用同样大的 (Q)，leaf 可能不再有 128-bit security。

---

# 2. 这不是“分解正确性”的问题，而是“参数安全性”的问题

我们已经在理论上说明：

[
\text{Split + leafBTS + Merge}
]

可能在明文语义上等价于大环 BTS。

但是密码学安全还要看：

1. Split 后 leaf ciphertext 是在什么密钥下加密？
2. leaf ring 的维度是多少？
3. leaf 使用的 modulus chain 多大？
4. leaf secret 是独立采样的，还是从 top secret 派生的？
5. ring-switching keys / merge keys / bootstrapping keys 是否泄露额外信息？
6. public evaluation keys 数量变多后，RLWE samples 是否仍然安全？
7. 是否引入 subring/subfield 相关攻击面？

这些都不由 correctness theorem 自动保证。

---

# 3. 如果 leaf ring 独立安全，那么组合通常有希望安全

可以把系统看成多个加密域：

* top ring (R_N)；
* leaf rings (R_n)；
* ring-switching keys；
* leaf bootstrapping keys；
* merge keys。

如果每一个域本身都是 IND-CPA secure 的 RLWE/CKKS 实例，并且 key-switching / ring-switching keys 可以被视为在目标 secret 下对源 secret 相关消息的安全加密，那么整体安全性通常可以通过 hybrid argument 继承。

类似的“在不同 LWE/RLWE ciphertext 形式之间转换”的思想在同态加密文献中是已有方向，例如 Chen--Dai--Kim--Song 的工作研究了在 LWE 与 RLWE ciphertext 之间进行同态转换和 key switching。([IACR Eprint Archive][2])

但这类安全性不是白来的。你要明确写出 assumptions：

[
\boxed{
\text{所有 public switching/evaluation keys 在相应 RLWE 假设下不泄露 secret。}
}
]

---

# 4. 最危险的点：小环维度下降

这是你现在最应该关注的。

假设原来 direct bootstrapping 用：

[
N,\quad Q.
]

factored route 用 leaf：

[
n=N/k,\quad Q_{\text{leaf}}.
]

如果：

[
Q_{\text{leaf}}\approx Q
]

但：

[
n=N/k
]

变小，那么安全性可能明显下降。

所以不能只说：

> 我们把大环 bootstrapping 拆成两个小环，速度快了。

必须补一句：

> leaf parameters 必须重新选取，保证 (R_n,Q_{\text{leaf}}) 本身满足目标 RLWE security。

安全性应该取最小值：

[
\lambda_{\text{system}}
=======================

\min{
\lambda_{\text{top}},
\lambda_{\text{leaf}},
\lambda_{\text{switching-keys}},
\lambda_{\text{bootstrapping-keys}}
}.
]

如果 leaf 只有 80-bit security，那整个系统最多就是 80-bit security。

---

# 5. 第二个危险点：secret 分布

如果 leaf secret 是独立采样的 dense secret，那比较好分析。

如果 leaf secret 是从 top secret 投影、trace、subring restriction 得来的，那就要小心：

[
s_N \longrightarrow s_n
]

这个派生 secret 的分布可能不是标准 RLWE secret 分布。

尤其是如果 top secret 是 sparse / ternary / hamming-weight secret，投影到 subring 后可能仍然很稀疏，甚至带有结构。近期 subring secret encapsulation 的工作明确提到“稀疏 secret 的潜在安全风险”，并提出在 bootstrapping 前切换到 subring dense secret 来缓解这个问题。([Springer Link][3])

这对你非常相关。

你的方案如果使用 leaf secret，最好考虑：

[
\boxed{
leaf secret 使用独立 dense secret，而不是简单继承/投影 sparse top secret。
}
]

或者至少要单独估算 projected secret 的安全性。

---

# 6. 第三个危险点：subring / subfield attack surface

由于你显式使用了 subring，必须考虑 algebraic attack surface。

RLWE 的安全依赖代数结构和参数选择，文献中常见风险包括 subfield attacks、special-root / smearing attacks 等。这个不是说你的方案一定有问题，而是说“使用子环结构”时必须说明为什么不会把 samples 限制到容易攻击的子结构。([Emergent Mind][1])

具体到你这里，要检查：

1. leaf ciphertext 是否只是普通 (R_n)-RLWE sample；
2. error 是否仍然有足够熵和正确分布；
3. secret 是否落入过小子空间；
4. public switching keys 是否暴露大量相关样本；
5. (q) 与 cyclotomic factors / roots modulo (q) 是否引入特殊攻击面。

如果 leaf ring 参数本来就是标准 CKKS 参数集支持的安全参数，这部分压力会小很多。
如果你自己构造了非标准小环参数，就要更谨慎。

---

# 7. ring-switching keys 也要算进安全模型

你的路线需要：

[
\Split
]

和

[
\Merge
]

对应的 ring-switching / key-switching keys。

这些 keys 是 public evaluation keys。它们通常可以被看成“某个 secret 或 secret 相关量的 RLWE 加密”。

因此安全性分析必须把它们也视为 adversary 可见的 samples。

要回答：

[
\boxed{
给出这些 switching keys 后，攻击者是否能更容易恢复 top secret 或 leaf secrets？
}
]

在同态加密中，key switching keys 公开是常见的，通常基于 RLWE/circular-security/KDM-like assumptions 处理。但在你的方案里，因为有多个 ring、多个 secret、subring maps，最好明确写出：

* top secret (s_N)；
* leaf secrets (s_{n,r})；
* split keys 是谁到谁；
* merge keys 是谁到谁；
* bootstrapping keys encrypt 什么；
* 这些 keys 的 RLWE 参数是多少。

---

# 8. 所以安全性分析要怎么写？

我建议把安全性章节分成下面几节。

## 8.1 Security goal

说明目标是：

> factored bootstrapping 不降低 CKKS 的 IND-CPA / semantic security 到目标位数以下。

注意：bootstrapping 是 evaluation procedure，不应该泄露明文，也不应该泄露 secret。

---

## 8.2 Parameter-level security

对每个 ring 单独估算：

[
(R_N,Q_N,\sigma,s_N)
]

和

[
(R_n,Q_n,\sigma,s_n)
]

的 RLWE security。

写成：

[
\lambda_N=\operatorname{EstimateRLWE}(N,Q_N,\sigma,\chi_s),
]

[
\lambda_n=\operatorname{EstimateRLWE}(n,Q_n,\sigma,\chi_s).
]

要求：

[
\min(\lambda_N,\lambda_n)\ge 128.
]

如果 (k>2)，还要对最小 leaf ring 估算。

---

## 8.3 Evaluation-key security

把所有 public keys 纳入：

* top relinearization keys；
* top bootstrapping keys；
* split/ring-switching keys；
* leaf bootstrapping keys；
* merge keys；
* rotation/Galois keys。

说明这些都是 RLWE samples 或 RLWE encryptions of secret-related values，安全性依赖相应 RLWE / key-switching assumptions。

---

## 8.4 Secret-distribution security

讨论 leaf secret 的来源：

### 情况 A：独立 leaf secrets

如果每个 leaf secret 独立采样：

[
s_{n,r}\leftarrow \chi_s
]

则安全性比较标准，但 key 管理成本更大。

### 情况 B：derived / projected secrets

如果：

[
s_{n,r}=\pi_r(s_N)
]

则必须分析 (\pi_r(s_N)) 的分布是否仍然安全。
特别要注意 sparse secret 是否变得更弱。

---

## 8.5 Subring attack surface

说明 leaf ciphertexts 是标准小环 RLWE，还是带有额外结构。

如果只是标准 (R_n)-RLWE，并且参数安全，则可以接受。

如果 samples 在某个更小子空间中，或者 secret/error 也在更小子环中，可能有 subfield 风险。

---

## 8.6 Composition theorem

最后写一个组合安全命题：

> 如果 top CKKS、leaf CKKS、所有 switching keys 在各自参数下满足 RLWE-based semantic security，且 switching keys 不泄露 secret，则 factored bootstrapping procedure 作为 public homomorphic evaluation 不降低安全性，系统安全性由最弱参数决定。

形式上：

[
\lambda_{\text{factored}}
=========================

\min
{
\lambda_{\text{top}},
\lambda_{\text{leaf}},
\lambda_{\text{eval-keys}}
}.
]

---

# 9. 对你的方案最现实的判断

我现在会这样判断：

[
\boxed{
理论 correctness 是有希望的；安全性不是天然成立，但也不是必然有问题。
}
]

关键取决于：

1. leaf ring 参数是否够安全；
2. leaf secret 是否安全采样；
3. ring-switching keys 是否按标准 key-switching 安全模型生成；
4. 是否避免 subring/subfield 相关弱结构；
5. key size 和 key generation 是否实际可接受。

最可能的安全瓶颈是：

[
\boxed{
n=N/k \text{ 变小，但 } Q \text{ 仍然很大，导致 leaf RLWE security 不够。}
}
]

所以你下一步不能只测速度和误差，必须跑安全估计。

---

# 10. 你这条路线如果要作为成果，安全性章节必须有

如果你要写成成果，不能只写：

[
\BTS_N
\approx
\frac{1}{k}
\Merge\circ(\oplus \BTS_n)\circ\Split.
]

必须加：

> The decomposition is correctness-preserving. Security requires that all leaf bootstrapping instances and all ring-switching/evaluation keys are instantiated with parameters meeting the target RLWE security level. In particular, the smaller ring dimension (n=N/k) may require a smaller modulus chain, denser secrets, or larger (n) to maintain security.

中文就是：

[
\boxed{
这个分解保持正确性；安全性取决于 leaf 参数和 switching keys，不能自动继承大环安全性。
}
]

---

# 11. 最短回答你的问题

是的，你说得对，关键必须分析安全性。

现在的理论说明：

[
\boxed{
大的 bootstrapping 可以在明文语义上拆成多个小环 bootstrapping。}
]

但密码学上还必须证明：

[
\boxed{
这些小环 bootstrapping 和 split/merge key switching 不会把安全性降到不可接受。}
]

尤其要检查：

[
\boxed{
leaf ring (R_{N/k}) 在所用 modulus chain 下是否还有足够 RLWE security。}
]

如果这个过不了，那么 correctness 再漂亮也不能作为安全方案。
