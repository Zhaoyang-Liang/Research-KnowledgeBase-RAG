对，这个点非常重要，而且我觉得它比前面那些“写清楚边界”的东西更实质。

你的压缩把计算从

[
R_{2n}=\mathbb Z_q[X]/(X^{2n}+1)
]

搬到

[
R_n=\mathbb Z_q[Y]/(Y^n+1).
]

代数上这是好事，复杂度下降；但安全上，**环维度减半以后，RLWE 安全性不能默认继承原来的大环安全性**。你的文档里已经把压缩理解成用一次小环 key switching 的代价，换取后续半维度小环计算的机会。 这个机会成立的前提是：小环本身仍然安全。

---

# 1. 为什么小环安全性要重新估计？

RLWE/CKKS 的安全性大致受这些量影响：

[
\text{ring degree } n,\quad
\text{ciphertext modulus } q,\quad
\text{error distribution } \chi_e,\quad
\text{secret distribution } \chi_s,\quad
\text{公开样本数量}.
]

你压缩之后，最关键的变化是：

[
2n \longrightarrow n.
]

如果模数 (q) 不变，环维度减半通常会让格攻击更容易。直觉上，攻击者面对的是更低维的 RLWE/LWE 实例，而模数大小、噪声大小没有相应缩小，安全余量会下降。HomomorphicEncryption.org 的安全指南页面也明确把安全参数表、攻击估计工具作为 FHE 参数选择的核心依据，2024 指南还提供更更新的安全表和常见 FHE 方案的功能参数示例。([homomorphicencryption.org][1])

所以你不能写：

> 原来 (R_{2n}) 是 128-bit secure，所以压缩到 (R_n) 后也安全。

更准确的是：

> 每一个实际参与加密、key switching 或后续计算的小环参数 ((n,q,\chi_s,\chi_e)) 都必须独立满足目标安全级别。

---

# 2. 对你的方案，哪些环需要估计安全？

假设你从初始大环一路递归：

[
R_N\to R_{N/2}\to R_{N/4}\to \cdots \to R_{N/2^d}.
]

那么不是只估计 (R_N)。你需要估计每一层：

[
R_{N/2^i},\qquad i=0,1,\dots,d.
]

第 (i) 层需要检查：

[
\lambda_i
=========

\operatorname{Sec}\left(
N/2^i,\ q_i,\ \chi_s^{(i)},\ \chi_e^{(i)},\ m_i
\right)
\ge \lambda_{\text{target}}.
]

这里：

* (N/2^i)：第 (i) 层环 degree；
* (q_i)：该层实际使用的 ciphertext modulus；
* (\chi_s^{(i)})：该层私钥分布；
* (\chi_e^{(i)})：该层加密/KS 错误分布；
* (m_i)：公开 RLWE 样本数量，包括 public key、rotation key、relinearization key、compression KSK 等。

最终安全级别应该取最小值：

[
\lambda_{\text{scheme}}
=======================

\min_i \lambda_i.
]

也就是说，整个递归方案的安全性由**最弱的小环层**决定。

---

# 3. 最危险的情况：维度降了，但模数链没降

如果你压缩后仍然保留同样大的 modulus：

[
q_{\text{small}}=q_{\text{large}},
]

那通常很危险。

比如大环参数是：

[
R_{32768},\quad q\approx 2^{900}.
]

压到：

[
R_{16384}
]

后，如果还用：

[
q\approx 2^{900},
]

那么小环安全性可能比大环低不少。

如果继续压到：

[
R_{8192},\quad R_{4096}
]

但还带着很大的 (q)，安全性可能直接不够。

所以你需要建立一个原则：

> 每次压缩到小环后，要么证明当前剩余 modulus 在该小环维度下仍安全，要么必须先 mod-down / rescale / 重新设计模数链，使 (q_i) 与小环维度匹配。

这个在 CKKS 里尤其关键，因为 bootstrapping 或深层计算可能需要很长 modulus chain。大环能承受的总 modulus，小环不一定能承受。

---

# 4. 对你的压缩 KSK，还要估计 evaluation key 的安全

你的压缩不是单纯把密文搬到小环。它需要公开 compression switching keys。

基础版需要：

[
KSK_0:s_0\to s',
\qquad
KSK_1:s_1\to s'.
]

优化版可能只需要：

[
KSK_{1\to 0}:s_1\to s_0.
]

这些 KSK 本身就是小环上的 RLWE 样本。HomomorphicEncryption.org 的安全指南页面列出 lattice estimator 作为常用的 LWE 安全估计工具，并说明该类工具用于帮助设计者选择能抵抗已知攻击的参数；lattice-estimator 也说明它会集成针对 LWE/NTRU/SIS 的已知攻击模拟，并给出基于格约化启发式的 bit-security 估计。([homomorphicencryption.org][1])

所以你需要把 compression KSK 也计入小环公开样本数量。也就是说，第 (i) 层不是只估计一两个普通密文，而是估计带有 evaluation keys 的 RLWE 实例。

如果第 (i) 层有 gadget 分解长度 (L_i)，那么：

* 双 KSK 版本给出大约 (2L_i) 个小环 RLWE 样本；
* 单边优化版本给出大约 (L_i) 个小环 RLWE 样本；
* 如果还有小环 rotation/relinearization keys，也要加进去。

样本数越多，攻击者信息越多。通常影响没有 (n,q) 那么大，但正式估计时不该忽略。

---

# 5. 还有一个细节：估计时要用哪个 modulus？

key switching key 往往不是只在普通 ciphertext modulus (Q) 下发布。有些实现会用扩展模数：

[
Q\cdot P
]

其中 (P) 是 special prime / auxiliary modulus，用于 key switching。

安全估计时应该保守使用公开样本所在的**最大 modulus**。也就是说：

* 普通小环密文用 (Q_i)；
* 如果 KSK 在 (Q_iP_i) 下发布，则 KSK 安全要用 (Q_iP_i)。

因此每层最好分别记录：

[
Q_i^{\mathrm{ct}}
]

和

[
Q_i^{\mathrm{ks}}.
]

然后要求：

[
\operatorname{Sec}(n_i,Q_i^{\mathrm{ct}},\chi_s,\chi_e)\ge \lambda,
]

[
\operatorname{Sec}(n_i,Q_i^{\mathrm{ks}},\chi_s,\chi_e,m_i^{\mathrm{ks}})\ge \lambda.
]

这个会让你的安全声明更稳。

# 6. 推荐你在文档中加入一个“参数安全条件”

可以写成一个 formal assumption。

## Assumption: Per-layer RLWE security

设递归压缩使用环塔：

[
R_{N_0},R_{N_1},\dots,R_{N_d},
\qquad
N_i=N_0/2^i.
]

第 (i) 层使用 ciphertext modulus (Q_i)，key-switching modulus (\widetilde Q_i)，secret distribution (\chi_s^{(i)})，error distribution (\chi_e^{(i)})，公开样本数量 (m_i)。

我们要求对所有 (i)：

[
\operatorname{RLWE}_{N_i,Q_i,\chi_s^{(i)},\chi_e^{(i)}}
]

和

[
\operatorname{RLWE}_{N_i,\widetilde Q_i,\chi_s^{(i)},\chi_e^{(i)}}
]

在目标安全级别 (\lambda) 下是困难的。

也可以更工程化地写：

[
\min_{0\le i\le d}
\operatorname{EstimateSecurity}
\left(
N_i,\widetilde Q_i,\chi_s^{(i)},\chi_e^{(i)},m_i
\right)
\ge
\lambda.
]

# 7. 参数设计原则

你可以给出几个 practical rules。

## 原则 1：越往小环走，modulus budget 必须下降

如果：

[
N_i=N_0/2^i,
]

那么一般应该让：

[
\log Q_i
]

也随 (i) 降低。

也就是说，你不能把大环上的完整 modulus chain 原封不动带到很小的环里。

更合理的是：

[
R_N\text{ 使用大 }Q,
]

[
R_{N/2}\text{ 使用较小 }Q,
]

[
R_{N/4}\text{ 使用更小 }Q.
]

这和你的递归 FFT 也吻合：越往下，分支更小，通常后续需要的深度也应该更少。

## 原则 2：压缩前最好先消耗或丢弃不需要的 modulus

如果某层压缩后不再需要那么多 level，可以在压缩前或压缩后做 mod-down：

[
Q_i\to Q_{i+1}.
]

这样既能控制噪声，也能提升小环安全性。

## 原则 3：不要递归压到太小的环

即使计算上继续压缩有收益，安全上也可能不允许。

应该存在一个最小环维度：

[
N_{\min}
]

满足：

[
\operatorname{Sec}(N_{\min},Q_{\min})\ge \lambda.
]

一旦下一层会低于目标安全级别，就停止递归压缩。

这可以作为算法参数：

[
\texttt{stop_degree}=N_{\min}.
]

## 原则 4：compression keys 的数量要进入估计

递归层数越多，compression KSK 越多。

虽然每层小环维度减半，key size 是几何下降，但安全估计上，每层都有额外 RLWE 样本。尤其如果你还为每层准备 rotation keys、merge keys、expansion keys，样本数量会增加。

所以要记录：

[
m_i
===

m_i^{\mathrm{pk}}
+
m_i^{\mathrm{rot}}
+
m_i^{\mathrm{rel}}
+
m_i^{\mathrm{comp}}
+
m_i^{\mathrm{expand}}.
]

# 8. 安全性和性能之间的核心 trade-off

你的方法的收益来自：

[
R_{2n}\to R_n
]

后续计算减半。

但安全成本是：

[
n\text{ 变小，允许的 }q\text{ 也变小}.
]

所以有一个核心 trade-off：

| 选择           | 好处        | 风险          |
| ------------ | --------- | ----------- |
| 压得更深         | 计算更快，密文更小 | 小环安全性下降     |
| 保留更大 (q)     | 支持更多层计算   | 小环安全性下降     |
| 压缩后 mod-down | 安全性更好     | 可用 level 减少 |
| 停在较大环        | 安全余量更大    | 计算收益变小      |

所以你后续实验里不能只测 runtime。还应该画出：

[
\text{ring degree} \quad vs \quad \log Q_{\max}\quad vs\quad \text{estimated security}.
]

这会非常有说服力。

这样比较稳。

# 11. 一个关键写法：压缩安全不由大环保证，而由小环 KSK 保证

你可以加一个 remark：

> Although the input ciphertext is generated in (R_{2n}), after compression the output ciphertext and compression switching keys live in (R_n). Therefore, the security of the compressed ciphertext is governed by the RLWE assumption over (R_n), not by the original RLWE assumption over (R_{2n}).

中文：

> 尽管压缩输入来自大环，压缩输出和压缩切换密钥都属于小环。因此压缩后密文的安全性由小环 RLWE 参数决定，而不是自动继承大环安全性。

这句话非常重要。

# 12. 对你方法的一个潜在积极点

这个安全提醒不全是坏消息。

因为你的压缩后计算发生在小环，**你也可以主动降低 modulus**。如果后续递归每层都不需要很深的乘法深度，那么小环可以使用明显更短的模数链。

也就是说，你的方法可以设计成：

[
\text{dimension decreases}
\quad\text{and}\quad
\text{modulus also decreases}.
]

这样既保留安全性，又降低计算成本。

这可能反而是你方法的一个设计亮点：

> The compression should be paired with modulus reduction so that both dimension and modulus shrink along the FFT recursion.

如果只降维不降模，安全可能变差；但如果降维同时降模，就可能形成一个安全且高效的多层参数塔。

# 13. 最推荐你补进文档的一段话

可以直接写：

> **Security of lower-dimensional rings.**
> The compression procedure maps a ciphertext over (R_{2n}) to a ciphertext over (R_n). Although correctness follows from the polynomial identity (m(X^2)\mapsto m(Y)), the security of the output ciphertext is not inherited automatically from the security of the input ring. Since the compressed ciphertexts and the compression switching keys are RLWE samples over (R_n), the RLWE parameters of (R_n), including the modulus used for ciphertexts and evaluation keys, must independently meet the target security level. In recursive applications, every ring in the tower (R_N,R_{N/2},R_{N/4},\dots) must be checked, and the effective security of the whole construction is the minimum security over all layers.

中文版本：

> **低维环安全性。**
> 压缩过程把 (R_{2n}) 上的密文转换为 (R_n) 上的密文。虽然正确性可以由多项式关系 (m(X^2)\mapsto m(Y)) 保证，但输出密文的安全性不会自动继承自大环。因为压缩后的密文以及压缩切换密钥都是 (R_n) 上的 RLWE 样本，所以 (R_n) 的环维度、密文模数、切换密钥模数、私钥分布、误差分布和公开样本数量都必须独立满足目标安全级别。在递归压缩中，需要对 (R_N,R_{N/2},R_{N/4},\dots) 每一层分别估计安全性，整体安全性取所有层中的最小值。

# 14. 最终建议

这个点你后续应该作为一个独立小节写，不要只放一句提醒。建议小节标题：

```text
4.x Security of the Ring-Dimension Reduction
```

里面包含：

1. 为什么小环安全不自动继承；
2. 每层 RLWE 参数必须独立估计；
3. KSK modulus 也要纳入；
4. compression KSK 样本数要纳入；
5. 递归安全取最小层；
6. 建议压缩配合 mod-down；
7. 给出一张实验参数安全表。

一句话总结：

> 你的压缩真正带来的不是“免费降维”，而是“在小环仍然安全的前提下降维”。因此，算法正确性之外，必须建立一个 per-layer RLWE security check：每次 (R_{2n}\to R_n) 后，都要重新检查 (n,q,\chi_s,\chi_e) 和 evaluation-key 样本数是否仍满足目标安全级别。
