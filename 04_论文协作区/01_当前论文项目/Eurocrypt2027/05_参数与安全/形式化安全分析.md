# Subring-Factored CKKS Bootstrapping 的形式化安全分析草案

> 状态：理论安全草案，尚未替代最终 lattice-estimator 参数表。  
> 目标：在 **leaf 仍使用 same public modulus \(Q\) / \(QP\)** 的保守设定下，说明安全参数由谁决定、哪些 \((N,k,n)\) 当前可作为安全候选、以及 split/merge 辅助密钥和 leaf ciphertexts 为什么不应额外泄露消息或 secret。

---

## 0. 本文需要证明的安全命题

正确性章节证明的是 ideal message-level factorization：

\[
\mathsf{S2C}_N\circ\mathsf{EvalMod}_N\circ\mathsf{C2S}_N
=
\mathsf{Merge}_k
\circ
\left(
\bigoplus_{r=0}^{k-1}
\mathsf{S2C}_n\circ\mathsf{EvalMod}_n\circ\mathsf{C2S}_n
\right)
\circ
\mathsf{Split}_k,
\qquad N=kn.
\]

安全章节要证明的是另一件事：

\[
\boxed{
\text{把 ciphertext route 分解到 leaf rings 后，不把 IND-CPA/security level 降到目标值以下。}
}
\]

这不是 correctness theorem 的直接推论。原因是 factored route 会公开或产生新的小环对象：

1. leaf ciphertexts over \(\mathcal R_{q,n}\);
2. \(\mathsf{RSDown}\) / \(\mathsf{RSUp}\) switching keys;
3. leaf bootstrapping keys, rotation keys, relinearization keys;
4. 可能还有 automorphism/Galois keys 和 hoisting keys。

这些对象的安全性由它们所在 ring 的 RLWE/Key-switching 参数决定。特别地：

\[
\boxed{
\text{leaf security is governed by }(n,q_{\max},\chi_s,\chi_e,m),
\text{ not by the top degree }N.
}
\]

---

## 1. 安全参数到底由谁决定？

对任何参与公开 RLWE samples 的 ring \(\mathcal R_{q,d}=\mathbb Z_q[X]/(X^d+1)\)，安全估计至少依赖：

\[
d,\qquad q_{\max},\qquad \chi_s,\qquad \chi_e,\qquad m.
\]

其中：

- \(d\)：ring degree。top 层是 \(N\)，leaf 层是 \(n=N/k\)。
- \(q_{\max}\)：该层 adversary 能看到的最大公开模数。
- \(\chi_s\)：secret distribution，例如 dense ternary、Gaussian、sparse ternary。
- \(\chi_e\)：encryption/key-switching error distribution。
- \(m\)：公开 samples 数量，包括 public key、switching keys、rotation keys、bootstrapping keys。

CKKS bootstrapping 里 \(q_{\max}\) 不能只取当前 ciphertext 的剩余 modulus \(Q_{\mathrm{ct}}\)。公开 evaluation keys 往往在 key-switching 或 bootstrapping 扩展模数下生成。因此保守写法是：

\[
q_{\max}^{(i)}
=
\max\{
Q_{\mathrm{ct}}^{(i)},
Q_{\mathrm{eval}}^{(i)},
Q_{\mathrm{rs}}^{(i)}P_{\mathrm{rs}}^{(i)},
Q_{\mathrm{bts}}^{(i)}P_{\mathrm{bts}}^{(i)}
\}.
\]

在当前 same-\(Q\) 讨论中，leaf 不能通过降低 \(Q\) 获得额外安全余量，因此 leaf 安全瓶颈可保守近似为：

\[
\lambda_{\mathrm{leaf}}
=
\operatorname{EstimateRLWE}
\left(
n,\ q_{\max}^{\mathrm{leaf}},\ \chi_s^{\mathrm{leaf}},\ \chi_e^{\mathrm{leaf}},\ m_{\mathrm{leaf}}
\right),
\qquad
q_{\max}^{\mathrm{leaf}}\approx QP.
\]

整个方案的可声称安全级别是最小值：

\[
\lambda_{\mathrm{scheme}}
=
\min
\left\{
\lambda_{\mathrm{top}},
\lambda_{\mathrm{leaf}},
\lambda_{\mathrm{RSDown}},
\lambda_{\mathrm{RSUp}},
\lambda_{\mathrm{BTSkeys}},
\lambda_{\mathrm{rot}},
\lambda_{\mathrm{rel}}
\right\}.
\]

因此只要某个 leaf 或 switching-key 参数只有 80-bit security，整个 factored bootstrapping route 最高只能声称 80-bit security。

## 2. Same-\(Q\) 约束下当前可用参数结论

本节只给 **security-aware positioning**，不替代最终 estimator bit 数。最终论文仍必须用 lattice estimator 或 HE standard methodology 对每一组 \(q_{\max}\) 填表。

### 2.1 设计约束

用户当前设定是：

\[
\boxed{
\text{leaf ring 中的 }Q\text{ 也不能改变，即不 claim reduced-}Q.
}
\]

于是当 \(N=kn\) 且 \(k>1\) 时，计算收益来自 \(n<N\)，但安全成本也来自 \(n<N\)。如果 \(Q\) / \(QP\) 仍保持大环 bootstrapping 级别，最小 leaf degree 必须独立足够大。

对于 CKKS bootstrapping 级别的大公开模数，本文当前应采用如下保守边界：

\[
\boxed{
n=2^{16}
\text{ 是当前主要安全候选 leaf degree；}
\quad
n=2^{15}
\text{ 不作为默认 128-bit 安全 leaf；}
\quad
2^{18}\text{ top degree 暂不作为本文可用主参数。}
}
\]

这里的逻辑不是说 \(2^{15}\) 在所有 \(Q\) 下都不安全，而是：

\[
\text{在 same large bootstrapping }QP\text{ 下，}2^{15}\text{ leaf 不能无 estimator 证明地声称安全。}
\]

### 2.2 推荐参数定位表

| Case | Top \(\log N\) | Split \(k\) | Leaf \(\log n\) | Same-\(Q\) 安全定位 | 论文中建议用法 |
|---|---:|---:|---:|---|---|
| Direct / baseline | 16 | 1 | 16 | 可作为 \(2^{16}\) 级别 baseline，仍需按实际 \(QP\) 估计 | 主 baseline 或小型实验 |
| Factored prototype | 16 | 2 | 15 | leaf 太小，same large \(QP\) 下不应默认 claim 128-bit | correctness/timing prototype |
| Factored prototype | 16 | 4 | 14 | leaf 更小，不应作为安全参数 | 只用于机制演示 |
| Main security-aware candidate | 17 | 2 | 16 | 当前最现实的 same-\(Q\) 安全候选 | 主安全候选，适合训练同态模型等较重场景 |
| \(k=4\) security-aware | 18 | 4 | 16 | leaf 可回到 \(2^{16}\)，但 top \(2^{18}\) 当前过重 | 本文不作为主可用方案 |
| Heavy future | 17 | 1 | 17 | 不拆分，安全余量和容量高但成本大 | 大模型/重 bootstrapping 场景参考 |

因此，在不考虑 \(2^{18}\) 的前提下，当前可写成：

\[
\boxed{
\text{本文的 same-}Q\text{ 安全主路线最多支持 }k=2\text{ 且使用 }N=2^{17},n=2^{16}.
}
\]

若坚持 \(N=2^{16}\)，则：

\[
k=1\text{ 是安全 baseline；}
\qquad
k=2\text{ 给出 }n=2^{15}\text{ leaf，只能作为 prototype，除非降低 }Q\text{ 或 estimator 证明足够安全。}
\]

若要在 same-\(Q\) 下支持 \(k=4\) 并保持 \(n=2^{16}\)，则必须取 \(N=2^{18}\)。按当前写作策略，\(2^{18}\) 不作为本文 practical target。

## 3. Threat model 和安全目标

### 3.1 Adversary view

攻击者可见：

\[
\mathsf{pp}
=
\left(
\mathsf{pk}_N,
\mathsf{evk}_N,
\{\mathsf{pk}_{n,r}\}_{r<k},
\{\mathsf{evk}_{n,r}\}_{r<k},
\mathsf{K}_{\mathrm{down}},
\mathsf{K}_{\mathrm{up}},
\text{all rotation/relinearization/bootstrapping keys}
\right).
\]

挑战密文可以是 top ciphertext，也可以包括 homomorphic evaluation 后的 factored-output ciphertext。攻击者也可以看到 evaluation algorithm 产生的公开 transcript，但不能得到 secret keys。

### 3.2 IND-CPA-style 目标

对任意两个等长消息多项式 \(P_0(X),P_1(X)\)，攻击者选择 \(b\leftarrow\{0,1\}\) 后得到：

\[
\ct^\star
\leftarrow
\operatorname{Enc}_{\mathsf{pk}_N}(P_b(X)).
\]

随后系统可以公开执行：

\[
\ct^\star
\mapsto
\mathsf{RSDown}(\ct^\star)
\mapsto
\left(\bigoplus_r \mathsf{BTS}_n\right)
\mapsto
\mathsf{RSUp}(\cdot),
\]

并把 evaluation keys 和输出 ciphertexts 给 adversary。安全目标是：

\[
\left|
\Pr[\mathcal A(\mathsf{view}_0)=1]
-
\Pr[\mathcal A(\mathsf{view}_1)=1]
\right|
\le
\operatorname{negl}(\lambda).
\]

对 approximate CKKS，消息空间应限制在合法 scale、合法 magnitude 和 correctness 区间内。这个限制影响 correctness/failure probability，不改变 IND-CPA hybrid 的基本形式。

## 4. 安全假设

### Assumption 1: Per-ring multi-sample RLWE pseudorandomness

对每个实际使用的 ring degree \(d\in\{N,n\}\)、最大公开模数 \(q_{\max}^{(d)}\)、secret distribution \(\chi_s^{(d)}\)、error distribution \(\chi_e^{(d)}\)、公开样本数量上界 \(m_d\)，RLWE samples

\[
(a_i,\ b_i=a_i s+e_i+\mu_i)\in \mathcal R_{q,d}^2
\]

在计算上不可区分于 uniform samples，即使 \(\mu_i\) 是 adversary 已知的 bounded plaintexts / gadget plaintexts。

这覆盖 public keys、ordinary ciphertexts、rotation keys、relinearization keys、bootstrapping keys 中的 RLWE encryptions。

### Assumption 2: Key-switching / ring-switching key indistinguishability

每个 switching key 都可以写成 target secret 下对 source secret 的 gadget digits 或线性函数的 RLWE encryption：

\[
\mathsf{K}_{s\to s'}
=
\left\{
\operatorname{Enc}_{s'}
\left(g_j(s)\right)
\right\}_{j=0}^{L-1}.
\]

要求这些 samples 在相应 target ring、target modulus 和 target secret distribution 下满足 Assumption 1。

如果某个 key encrypts a function of the same secret under itself，例如 relinearization key 或某些 automorphism key，则需要采用标准 HE key-switching 分析中的 circular/KDM-style assumption，或者在实现中使用独立 evaluation secret 规避明显循环。本文应明确写成：

\[
\boxed{
\text{All switching and evaluation keys are assumed pseudorandom under the corresponding RLWE/KDM setting.}
}
\]

### Assumption 3: Leaf secrets are standard and not projected sparse secrets

安全主张应优先使用独立 leaf secrets：

\[
s_{n,r}\leftarrow \chi_s^{(n)}
\quad\text{independently for }r=0,\ldots,k-1.
\]

不建议把 leaf secret 简写为 top secret 的 coefficient projection：

\[
s_{n,r}=\pi_r(s_N)
\]

后直接套用标准 RLWE 安全。若 top secret 是 sparse ternary 或固定 Hamming weight，投影后可能产生更弱或更结构化的分布。任何 projected-secret 版本都必须单独估计并说明分布。

因此本文当前推荐：

\[
\boxed{
\text{Main security claim uses independently sampled dense leaf secrets, or at least estimator-validated leaf secret distributions.}
}
\]

## 5. Split/Merge 辅助密钥是否泄露信息？

### 5.1 密文层面的 split 不是明文公开分解

虽然 message-level split 满足：

\[
P(X)=\sum_{r=0}^{k-1}X^rP_r(X^k),
\]

但 ciphertext-level \(\mathsf{RSDown}\) 不应被描述成“公开取出 \(P_r(Y)\)”。实际发生的是：

\[
\ct_N\vDash_N P(X)
\quad\longmapsto\quad
(\ct_{n,0},\ldots,\ct_{n,k-1}),
\qquad
\ct_{n,r}\vDash_n P_r(Y),
\]

其中每个 \(\ct_{n,r}\) 是在 leaf secret 下的 RLWE/CKKS ciphertext。攻击者看到的是加密后的 \(P_r(Y)\)，不是明文 \(P_r(Y)\)。

若 leaf encryption scheme 满足 IND-CPA，则公开多个 leaf ciphertexts 不泄露 \(P_r(Y)\)，因此也不泄露 \(P(X)\)。形式上，因为

\[
P(X)\longleftrightarrow (P_0(Y),\ldots,P_{k-1}(Y))
\]

是确定性可逆编码，保护所有 leaf messages 的 IND-CPA 安全等价于保护原消息的 IND-CPA 安全。

### 5.2 Switching keys 公开的是 secret-related encryptions，不是 secret

\(\mathsf{RSDown}\) / \(\mathsf{RSUp}\) keys 公开后，攻击者获得的是若干 RLWE encryptions of gadget/plaintext functions of secrets。安全性由 Assumption 2 给出。

一个标准 hybrid 可以这样写：

1. 将 top public key 和 top challenge ciphertext 替换为 uniform RLWE samples，损失 \(\epsilon_{\mathrm{top}}\)。
2. 将每个 \(\mathsf{RSDown}\) key 的 RLWE encryption 替换为 uniform，损失 \(\epsilon_{\mathrm{down}}\)。
3. 将每个 leaf public/evaluation/bootstrapping key 替换为 uniform，损失 \(\epsilon_{\mathrm{leaf}}\)。
4. 将每个 \(\mathsf{RSUp}\) key 替换为 uniform，损失 \(\epsilon_{\mathrm{up}}\)。
5. 在全 uniform hybrid 中，adversary view 与 challenge bit \(b\) 独立。

于是：

\[
\operatorname{Adv}_{\mathrm{factored}}^{\mathrm{ind}}
\le
\epsilon_{\mathrm{top}}
+\epsilon_{\mathrm{down}}
+\epsilon_{\mathrm{leaf}}
+\epsilon_{\mathrm{up}}
+\epsilon_{\mathrm{bts}}
+\epsilon_{\mathrm{rot}}
+\epsilon_{\mathrm{rel}}.
\]

若所有组件都满足 \(\lambda\)-bit security，并且公开样本数量已计入估计，则：

\[
\operatorname{Adv}_{\mathrm{factored}}^{\mathrm{ind}}
\le
\operatorname{poly}(m)\cdot 2^{-\lambda}.
\]

这说明 split/merge auxiliary keys 不给出额外明文泄露；它们只把安全负担转移到相应 ring 的 multi-sample RLWE/KDM assumptions 上。

## 6. Leaf ciphertexts 是否泄露更多信息？

Leaf route 会把一个 top ciphertext 转成 \(k\) 个 leaf ciphertexts。直觉上 adversary 看到更多 ciphertexts，因此需要说明“更多 ciphertexts”不会泄露更多消息。

证明方式是普通 IND-CPA composition。

设：

\[
\mathbf P
=
(P_0(Y),\ldots,P_{k-1}(Y)).
\]

若每个 leaf encryption oracle 在 independent leaf secret 下 IND-CPA secure，则 product encryption

\[
\operatorname{Enc}^{\oplus k}(\mathbf P)
=
(
\operatorname{Enc}_{s_{n,0}}(P_0(Y)),
\ldots,
\operatorname{Enc}_{s_{n,k-1}}(P_{k-1}(Y))
)
\]

也是 IND-CPA secure。Hybrid 逐个替换 leaf ciphertext：

\[
\operatorname{Enc}_{s_{n,r}}(P_{b,r}(Y))
\approx_c
\operatorname{Enc}_{s_{n,r}}(0).
\]

总损失最多是各 leaf advantage 之和：

\[
\operatorname{Adv}_{\oplus k}
\le
\sum_{r=0}^{k-1}
\operatorname{Adv}_{\mathrm{RLWE}(n,q_{\max},\chi_s,\chi_e,m_r)}.
\]

因此，多 leaf ciphertexts 本身不破坏 IND-CPA；真正的条件是每个 leaf ring 参数必须足够安全。

## 7. Subring/subfield 风险如何表述？

本文使用 subring structure，但安全样本不应落入更小的公开子空间。

安全版实现应满足：

1. leaf ciphertexts 是标准 \(\mathcal R_{q,n}\)-RLWE/CKKS ciphertexts，而不是只在 \(\mathcal R_{q,n}\) 的更小 submodule 中变化；
2. leaf errors 按标准 \(\chi_e^{(n)}\) 采样，不是 deterministic projection error；
3. leaf secrets 按标准 \(\chi_s^{(n)}\) 采样，或经过 estimator 验证；
4. switching keys 的 \(a\)-components 在目标 ring 中近似 uniform；
5. primes / NTT roots / cyclotomic choices 遵循标准 power-of-two CKKS 参数生成方式。

这样可以把 adversary 看到的对象规约为普通小环 RLWE samples，而不是额外结构化的 subfield samples。

## 8. Theorem: Factored route 的组合 IND-CPA 安全

### Theorem 8.1

Consider the ciphertext-level subring-factored bootstrapping route with \(N=kn\):

\[
\ct_N
\xrightarrow{\mathsf{RSDown}}
(\ct_{n,0},\ldots,\ct_{n,k-1})
\xrightarrow{\oplus_r\mathsf{BTS}_{n,r}}
(\ct'_{n,0},\ldots,\ct'_{n,k-1})
\xrightarrow{\mathsf{RSUp}}
\ct'_N.
\]

Assume:

1. top CKKS encryption over \(\mathcal R_{q,N}\) is IND-CPA secure under its multi-sample RLWE parameters;
2. for every leaf \(r\), CKKS encryption over \(\mathcal R_{q,n}\) is IND-CPA secure under its multi-sample RLWE parameters;
3. all \(\mathsf{RSDown}\), \(\mathsf{RSUp}\), rotation, relinearization, and bootstrapping keys are pseudorandom under the relevant RLWE/KDM key-switching assumptions at their maximum public moduli;
4. leaf secrets are independently sampled from the claimed leaf secret distribution, or their derived distribution is explicitly included in the estimator/security assumption;
5. all public samples are counted in \(m\), including gadget decomposition length and all evaluation-key components.

Then the public factored bootstrapping evaluation is IND-CPA preserving. More precisely, for any PPT adversary \(\mathcal A\),

\[
\operatorname{Adv}_{\mathcal A}^{\mathrm{factored}}
\le
\operatorname{Adv}_{N}^{\mathrm{RLWE}}
+
\sum_{r=0}^{k-1}\operatorname{Adv}_{n,r}^{\mathrm{RLWE}}
+
\operatorname{Adv}_{\mathrm{RSDown}}
+
\operatorname{Adv}_{\mathrm{RSUp}}
+
\operatorname{Adv}_{\mathrm{evalkeys}}.
\]

Consequently, the concrete security level of the factored route is:

\[
\lambda_{\mathrm{factored}}
=
\min
\left\{
\lambda_N,
\min_r\lambda_{n,r},
\lambda_{\mathrm{RSDown}},
\lambda_{\mathrm{RSUp}},
\lambda_{\mathrm{evalkeys}}
\right\}
-O(\log m_{\mathrm{tot}}).
\]

The \(O(\log m_{\mathrm{tot}})\) term denotes the usual loss from a union/hybrid over all public samples and keys; in practice it is handled by giving the estimator the relevant sample count or by taking a conservative security margin.

### Proof sketch

Bootstrapping, split, merge, rotations and linear transforms are public homomorphic algorithms applied to ciphertexts plus public evaluation keys. Public evaluation cannot reduce semantic security except through the public keys it reveals.

Construct a hybrid sequence. First replace the top challenge ciphertext and top public/evaluation keys by uniform samples using top-ring RLWE security. Then replace \(\mathsf{RSDown}\) keys by uniform samples under the target leaf rings. Then replace every leaf ciphertext and leaf bootstrapping/evaluation key by uniform samples using leaf-ring RLWE/KDM assumptions. Finally replace \(\mathsf{RSUp}\) keys by uniform samples under top-ring target parameters. In the final hybrid, the adversary's entire view consists of uniform samples and public deterministic outputs independent of the challenge bit \(b\). The distinguishing advantage is bounded by the sum of all hybrid losses.

This proof is deliberately modular: it does not say leaf security follows from top security. It says the construction is secure if every top, leaf, and switching-key RLWE instance is secure under its own parameters.

## 9. 当前论文应该怎样写安全 claim？

### Recommended claim

> The algebraic factorization is correctness-preserving. Its security is parameter-conditional: every leaf ciphertext and every switching/evaluation key must be instantiated with RLWE parameters meeting the target security level at the maximum public modulus used by that object. Under the standard multi-sample RLWE and key-switching/KDM assumptions for these parameters, the factored route is IND-CPA preserving by a hybrid argument. In the same-\(Q\) setting considered here, the security bottleneck is the minimum leaf degree \(n=N/k\).

### Same-\(Q\) practical conclusion

在不 claim reduced-\(Q\)、不把 \(2^{18}\) 作为当前 practical target 的情况下：

\[
\boxed{
(\log N,k,\log n)=(17,2,16)
\text{ 是当前唯一合理的 factored same-}Q\text{ 主安全候选。}
}
\]

\[
\boxed{
(\log N,k,\log n)=(16,2,15)
\text{ 和 }(16,4,14)
\text{ 只能作为 correctness/performance prototype。}
}
\]

\[
\boxed{
k=4\text{ 若要求 leaf }n=2^{16}\text{，需要 top }N=2^{18};
\text{ 本文当前不把它列为可用主方案。}
}
\]

### 不能写的 claim

不应写：

\[
\text{Top }N=2^{16}\text{ 安全，所以 split 到 }n=2^{15}\text{ 后也安全。}
\]

也不应写：

\[
\text{Correctness factorization theorem implies cryptographic security.}
\]

正确写法是：

\[
\text{Correctness factorization + per-layer RLWE security estimates}
\Rightarrow
\text{secure instantiation.}
\]

## 11. 与 Anyu Wang / Subring Secret Encapsulation 和 HERMES 的关系

Anyu Wang 等人的 subring secret encapsulation 强调 sparse secrets 的安全理解不足，并通过 bootstrapping 前切换到 dense subring secret，把安全基础放回 dense-secret LWE/RLWE。本文应吸收这个教训：不要把 sparse projected leaf secrets 直接当作标准安全分布；main security claim 应采用独立 dense leaf secrets 或 estimator-validated distributions。

HERMES 证明了 ring switching / ring packing 可以作为高效 backend 使用，但 HERMES 的任务是 LWE/MLWE-to-RLWE packing/transciphering，不是本文的 CKKS self-bootstrapping core factorization。因此 HERMES 的参数不能直接替代本文的 leaf security table。本文可以使用 HERMES-style ring switching 作为实现工具，但仍必须对本文暴露的 leaf ciphertexts、RSDown/RSUp keys 和 leaf bootstrapping keys 分别估计安全。

## 12. References / sources to verify

- HomomorphicEncryption.org, *Homomorphic Encryption Standard* and security guideline updates: used for the general rule that HE parameters must be chosen from security estimates/tables and that \(N\), modulus, secret/error distributions determine security.
- malb/lattice-estimator: used as the intended tool for concrete LWE/RLWE-style bit-security estimation.
- Curtis--Player, *On the Feasibility and Impact of Standardising Sparse-secret LWE Parameter Sets for Homomorphic Encryption*: useful background that practical CKKS/BFV/BGV bootstrapping often uses sparse secrets and large dimensions such as \(2^{16}\) or \(2^{17}\), while sparse-secret standardization is delicate.
- Ma--Huang--Wang--Wang, *Practical Dense-Key Bootstrapping with Subring Secret Encapsulation*: used for the warning that sparse-secret security is not fully understood and for the dense subring secret positioning.
- Bae--Cheon--Kim--Park--Stehle, *HERMES*: used for ring switching/ring packing context, not as a direct security proof for this construction.
