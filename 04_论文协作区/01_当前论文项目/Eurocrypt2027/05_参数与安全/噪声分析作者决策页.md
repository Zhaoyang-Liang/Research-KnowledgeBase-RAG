## 一、当前最关键的 3 个作者决策

### 决策 A：当前论文是否 claim reduced-Q leaf bootstrapping？

**问题**：leaf bootstrapping 是否可以在比 top direct bootstrapping 更低的模数下运行？

**选项**：

| 选择 | 含义 |
|------|------|
| **Yes, claim reduced-Q** | 论文明确声称 leaf 可以在更低 Q 下工作，作为一个额外贡献（资源节省）。需提供 proof 或 strong evidence。 |
| **No, same-Q** | leaf 和 top 使用相同模数。噪声分析会简化（只分析 split/merge overhead），但失去一个 contribution angle。 |
| **暂不 claim** | 论文不提 reduced-Q，留作 future work。 |

---

### 决策 B：当前论文是否需要完整 formal noise theorem？

**问题**：noise/correctness 是写成一个 formal theorem（带 ε, δ, Pr[fail] ≤ …）还是 informal analysis paragraph？

**选项**：

| 选择 | 含义 |
|------|------|
| **Formal theorem** | 写出类似 Pr[‖Dec(factored) − m‖_∞ > ε] ≤ δ 的语句。需要填所有 P0 缺口（KS bound、EvalMod ε_poly 等）。权威性强，但工作量大。 |
| **Informal analysis** | 用 qualitative argument + 实验误差数据支撑。写作快，但 reviewer 可能要求补 formal analysis。 |
| **Hybrid** | 主文写 informal + reference to full version appendix。折中方案。 |

---

### 决策 C：Split / Merge / RS / KS noise 写在哪里？

**问题**：这些 noise source 的分析放进 main body、appendix、limitation、还是 future work？

**选项**：

| 选择 | 含义 |
|------|------|
| **Main body** | 全部写进主文。fornal 程度最高，但占用页面（Eurocrypt 通常 ~30 页）。 |
| **Appendix** | 主文只写核心 correctness statement + experimental validation，noise derivation 放附录。 |
| **Limitation / Future work** | 主动承认"当前未做完整 noise bound"，作为局限性。降低 reviewer 期望。 |
