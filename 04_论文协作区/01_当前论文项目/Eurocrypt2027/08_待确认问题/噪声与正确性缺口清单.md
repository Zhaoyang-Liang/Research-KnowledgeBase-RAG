## P0：影响当前论文 correctness 的缺口

### P0-1：Split_k 是否引入额外误差

**当前理解**：如果 Split 是纯 coefficient rearrangement（如 HERMES 的 direct sum 观点），噪声为零。如果伴随 key/ring switching，则引入 KS 噪声。

**缺口**：
- [ ] 作者确认：当前实现中 Split 是否带 key switching？
- [ ] 如果带 KS：KS 次数 = ? 每次噪声界 = ?
- [ ] 文献依据：HERMES 的 coefficient rearrangement baseline

**来源**：src_000037（复杂度分析初步.md）、src_000038（噪声与成功概率分析.md §4.4）

**状态**：open_gap, needs_author_derivation

### P0-2：Merge_k 是否引入额外误差

**当前理解**：与 Split 对称。纯 rearrangement → 零噪声。带 KS → KS 噪声。

**缺口**：
- [ ] 作者确认：当前实现中 Merge 是否带 key switching？
- [ ] 如果带 KS：噪声界 = ?

**来源**：src_000037、src_000038 §4.9

**状态**：open_gap, needs_author_derivation

### P0-3：RSDown / RSUp ring switching noise

**当前理解**：Ring switching 本质是 key switching + 换环，噪声模型可归约为 KS 噪声之和。复杂度分析中已给递归公式。

**缺口**：
- [ ] 确认 RS 的具体次数（k=2 → 1层, k=4 → 2层）
- [ ] 每次 RS 的 KS 噪声是否需要单独 bound
- [ ] ring switching key 的安全性分析（独立于 correctness）

**来源**：src_000037 §5、src_000038 §4.5

**状态**：open_gap, needs_author_derivation

### P0-4：Key switching noise 如何叠加到最终 error

**当前理解**：src_000038 §4.5 给出：
- 每次 KS: |e_KS|_∞ ≤ B_KS with probability 1-δ_KS
- 总 KS 次数 M_KS 下 union bound: δ_KS,total ≤ M_KS·δ_KS
- 噪声保守相加 B_KS,total ≤ M_KS·B_KS（或 subgaussian √M_KS）

**缺口**：
- [ ] 论文中具体的 M_KS（全路径 KS 调用次数）
- [ ] 论文选择 conservative linear bound 还是 subgaussian bound
- [ ] B_KS 的具体数值（需要 secret distribution + 模数参数）

**来源**：src_000038 §4.5

**状态**：open_gap, needs_author_derivation

### P0-5：Leaf bootstrapping error 是否能合并回 top-level error

**当前理解**：src_000038 给出框架：
- 每个 leaf r 的噪声路径：B_0 → B_1 → B_2 → B_3 → B_4 → B_5
- 用线性变换范数 L_{C2S,n}, L_{Eval}, L_{S2C,n} 连接各层
- 最终 B_fac ≤ |γ_impl|⁻¹·(L_Merge·B_5 + B_Merge)

**缺口**：
- [ ] L_{C2S,n}, L_{S2C,n} 的精确范数值
- [ ] L_Eval 的 Lipschitz 常数（依赖 degree d, 区间 [-K,K]）
- [ ] B_Eval,arith（EvalMod 内的 rescale/乘法/relin 噪声）
- [ ] ε_poly 近似误差（EvalMod 多项式对 mod-1 的 sup-norm 误差）

**来源**：src_000038 §4.3-4.9

**状态**：open_gap, needs_author_derivation（框架已有，数值待填）

### P0-6：γ_impl 是否只是实现归一化，不进入数学 noise bound

**当前理解**：src_000036（归一化原因进一步解释.md）详细分析：
- γ_impl 来自 Lattigo bootstrapping 的 MessageRatio/ScaleDown/EvalMod/S2C scaling 管理
- 是 deterministic implementation-scaling correction，非经验拟合
- 对某些参数（logN=17, k=2）γ_impl=1，对另一些（logN=16, k=2）γ_impl=2

**缺口**：
- [ ] 作者确认：论文主定理中用 γ_impl 还是忽略它（claim 在特定参数下 γ_impl=1）？
- [ ] 如果部分参数 γ_impl≠1，论文是否需要说明 normalization convention

**来源**：src_000036

**状态**：candidate_analysis（作者已完成分析），needs_author_confirmation

### P0-7：Reduced-Q leaf bootstrapping 是否成立

**当前理解**：无直接材料。复杂度分析中提到 security 参数迫使 top N 增大（safe k=2 → logN_top=17），但未讨论 reduced-Q。

**缺口**：
- [ ] 叶子 bootstrapping 是否可在降低的模数下运行
- [ ] 如果降低 Q_leaf，EvalMod 是否能正常工作
- [ ] 降低 Q_leaf 的安全性影响

**来源**：无直接材料

**状态**：open_gap（最显著的缺口之一）

### P0-8：当前论文是否需要完整 noise theorem

**当前理解**：src_000038 §8-9 给出 proposition 草稿，但没有最终 statement。

**缺口**：
