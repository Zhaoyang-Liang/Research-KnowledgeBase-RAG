下面我把复杂度和开销分析整理成一个比较系统的版本。你可以把它当成报告/论文里的 **“Complexity and Overhead Analysis”** 草稿。

核心观点先说：

[
\boxed{
\text{你的 factored no-}B_k\text{ 方法的收益来自把一个大环 bootstrapping core 拆成多个小环 core。}
}
]

代价是：

[
\boxed{
\text{Split/Merge ring switching 开销}
+
\text{额外 key material}
+
\text{并行工作内存}
+
\text{为了安全而增大 top }N.
}
]

---

# 1. 预备知识和符号

设 top ring 为：

[
R_{q,N}=\mathbb Z_q[X]/(X^N+1).
]

拆分因子为：

[
k=2^\ell.
]

leaf ring degree 为：

[
n=\frac{N}{k}.
]

所以：

[
R_{q,N}
\simeq
\bigoplus_{r=0}^{k-1} R_{q,n}\cdot X_N^r.
]

HERMES 正是用这种 module view 来解释 ring switching：当 (k\mid N) 时，大环 (R_{q,N}) 可以看作小环 (R_{q,N/k}) 上 rank-(k) module，并定义 module decomposition map

[
\pi^k_{q,N}:R_{q,N}\to (R_{q,N/k})^k.
]

HERMES 进一步说明，在 coefficients-encoded CKKS 中，Split/Combine 的代数部分是 direct sum，也就是 coefficient rearrangement，因此单纯 Split/Combine 本身几乎没有计算成本。

我们用以下符号：

| 符号                    | 含义                               |
| --------------------- | -------------------------------- |
| (N)                   | top ring degree                  |
| (n=N/k)               | leaf ring degree                 |
| (k)                   | split factor / leaves 数          |
| (L_Q)                 | (Q)-basis 中 RNS primes 数         |
| (L_P)                 | (P)-basis 中 auxiliary primes 数   |
| (Q)                   | CKKS main modulus chain          |
| (P)                   | key switching auxiliary modulus  |
| (QP)                  | key switching / eval key 使用的最大模数 |
| (w)                   | leaf workers 数                   |
| (\eta_{\mathrm{par}}) | 并行效率，(0<\eta_{\mathrm{par}}\le1) |

---

# 2. 基础代价模型

## 2.1 RNS ring operation

一次 RNS 多项式运算，尤其是 NTT-dominated operation，可以粗略写成：

[
\boxed{
\mathsf{RingOp}(d,L)
====================

\Theta(L\cdot d\log d).
}
]

其中：

* (d) 是 ring degree；
* (L) 是当前 modulus basis 的 prime 数量。

如果只在 (Q) 上操作：

[
L=L_Q.
]

如果进入 key switching 的 (QP) basis：

[
L=L_Q+L_P.
]

所以：

[
\mathsf{RingOp}_Q(d)=\Theta(L_Q d\log d),
]

[
\mathsf{RingOp}_{QP}(d)=\Theta((L_Q+L_P)d\log d).
]

---

## 2.2 Key switching 代价

HERMES 把 RLWE key switching 拆成三个子步骤：

[
\mathrm{ModUp},
\qquad
\mathrm{MultSwk},
\qquad
\mathrm{ModDown}.
]

它的流程是：

[
\mathrm{KS}(ct;\mathrm{swk})
============================

\mathrm{ModDown}
\left(
\mathrm{MultSwk}(\mathrm{ModUp}(a),\mathrm{swk})
\right)
+(b,0).
]

HERMES 明确说，ModUp 和 ModDown 由 degree-(N) NTT 主导，复杂度是 (O(N\log N))，Hadamard multiplication 是 (O(N))，一个 switching key 的大小是 (2N\log(qp))。

因此，对 degree (d) 的 key switching，可以写成：

[
\boxed{
\mathsf{KS}(d,Q,P)
==================

\mathsf{ModUp}(d,Q,P)
+
\mathsf{MultSwk}(d,Q,P)
+
\mathsf{ModDown}(d,Q,P).
}
]

粗略主项是：

[
\boxed{
\mathsf{KS}(d,Q,P)
==================

\Theta((L_Q+L_P)d\log d).
}
]

更细一点：

[
\mathsf{KS}(d,Q,P)
==================

c_{\mathrm{up}}(L_Q,L_P)d\log d
+
c_{\mathrm{swk}}(L_Q,L_P)d
+
c_{\mathrm{down}}(L_Q,L_P)d\log d.
]

由于 ModUp/ModDown 是 (d\log d)，而 MultSwk 是 (d)，通常主导项是：

[
\boxed{
\mathsf{ModUp}+\mathsf{ModDown}.
}
]

这和 HERMES 的 ModPack 分析一致：他们在比较复杂度时主要关注 ModUp/ModDown，因为它们比 Hadamard multiplication 更重。

---

# 3. Direct bootstrapping 的复杂度

你的 direct full bootstrapping 是：

[
\ScaleDown_N
\rightarrow
\ModUp_N
\rightarrow
\CtwoS_N
\rightarrow
\EvalMod_N
\rightarrow
\StwoC_N.
]

因此：

[
\boxed{
T_{\mathrm{dir}}(N)
===================

T_{\ScaleDown}(N)
+
T_{\ModUp}(N)
+
T_{\CtwoS}(N)
+
T_{\EvalMod}(N)
+
T_{\StwoC}(N).
}
]

为了后续分析，把它拆成 shared part 和 core part：

[
T_{\mathrm{dir}}(N)
===================

T_{\mathrm{shared}}(N)
+
T_{\mathrm{core}}(N),
]

其中：

[
\boxed{
T_{\mathrm{shared}}(N)
======================

T_{\ScaleDown}(N)+T_{\ModUp}(N),
}
]

[
\boxed{
T_{\mathrm{core}}(N)
====================

T_{\CtwoS}(N)+T_{\EvalMod}(N)+T_{\StwoC}(N).
}
]

你的 no-(B_k) 分解主要加速的是：

[
\boxed{
T_{\mathrm{core}}(N).
}
]

它并没有直接加速 top-level 的 ScaleDown 和 ModUp，因为这两步仍然在 top ring (R_N) 上完成。

---

## 3.1 (\CtwoS_N) 和 (\StwoC_N)

(\CtwoS) 和 (\StwoC) 本质上是同态线性变换。HERMES 对 CKKS bootstrapping 的描述中也说，StC 是 homomorphic DFT matrix evaluation，CtS 是 homomorphic iDFT matrix evaluation；CtS 和 EvalMod 会消耗 modulus。

可以抽象成：

[
T_{\CtwoS}(N)
=============

r_{\CtwoS}(N)\cdot \mathsf{KS}(N,Q,P)
+
m_{\CtwoS}(N)\cdot \mathsf{RingOp}_Q(N),
]

[
T_{\StwoC}(N)
=============

r_{\StwoC}(N)\cdot \mathsf{KS}(N,Q,P)
+
m_{\StwoC}(N)\cdot \mathsf{RingOp}_Q(N).
]

其中：

* (r_{\CtwoS}(N))、(r_{\StwoC}(N)) 是 rotation/key-switch 数量；
* (m_{\CtwoS}(N))、(m_{\StwoC}(N)) 是 plaintext diagonal multiplication / addition / rescale 等线性变换内部操作数量。

由于 rotation 需要 key switching，所以 C2S/S2C 通常是 bootstrapping 里非常重的部分。

---

## 3.2 (\EvalMod_N)

EvalMod 是近似模约化函数的多项式计算。可以写成：

[
T_{\EvalMod}(N)
===============

m_{\EvalMod}(N)\cdot \mathsf{RingOp}*Q(N)
+
r*{\EvalMod}(N)\cdot \mathsf{KS}(N,Q,P).
]

如果 EvalMod 内部只做乘法、rescale、relinearization，那么 (r_{\EvalMod}) 主要来自 relinearization key switching。若有更多结构化操作，也可能包含额外 rotations。

由于 EvalMod 的 degree、double-angle 次数、rescale 层数都固定后，通常可以用：

[
T_{\EvalMod}(N)
\approx
c_{\EvalMod}\cdot \mathsf{RingOp}*Q(N)
+
c*{\mathrm{relin}}\cdot \mathsf{KS}(N,Q,P)
]

来建模。

---

# 4. Factored no-(B_k) bootstrapping 的复杂度

你的 factored full path 是：

[
\ScaleDown_N
\rightarrow
\ModUp_N
\rightarrow
\Split_{N\to n}^{(k)}
\rightarrow
\bigoplus_{r=0}^{k-1}
\left(
\CtwoS_n
\rightarrow
\EvalMod_n
\rightarrow
\StwoC_n
\right)
\rightarrow
\Merge_{n\to N}^{(k)}.
]

因此：

[
\boxed{
T_{\mathrm{fac}}(N,k)
=====================

T_{\ScaleDown}(N)
+
T_{\ModUp}(N)
+
T_{\Split}(N,k)
+
T_{\mathrm{leaf}}^{\parallel}(n,k,w)
+
T_{\Merge}(N,k)
+
T_{\mathrm{sync}}.
}
]

也就是：

[
\boxed{
T_{\mathrm{fac}}(N,k)
=====================

T_{\mathrm{shared}}(N)
+
T_{\Split}(N,k)
+
T_{\mathrm{leaf}}^{\parallel}(n,k,w)
+
T_{\Merge}(N,k)
+
T_{\mathrm{sync}}.
}
]

---

## 4.1 Leaf core

单个 leaf core 是：

[
T_{\mathrm{core}}(n)
====================

T_{\CtwoS}(n)+T_{\EvalMod}(n)+T_{\StwoC}(n).
]

如果 (k) 个 leaf 串行运行：

[
\boxed{
T_{\mathrm{leaf}}^{\mathrm{serial}}(n,k)
========================================

k\cdot T_{\mathrm{core}}(n).
}
]

如果 (k) 个 leaf 并行运行，使用 (w) 个 workers，理想情况下：

[
T_{\mathrm{leaf}}^{\parallel}(n,k,w)
\approx
\left\lceil\frac{k}{w}\right\rceil
T_{\mathrm{core}}(n).
]

考虑并行效率 (\eta_{\mathrm{par}})，更实际地写：

[
\boxed{
T_{\mathrm{leaf}}^{\parallel}(n,k,w)
\approx
\frac{k}{\min(k,w)\eta_{\mathrm{par}}}
T_{\mathrm{core}}(n).
}
]

当：

[
w=k,\qquad \eta_{\mathrm{par}}\approx1,
]

则：

[
\boxed{
T_{\mathrm{leaf}}^{\parallel}(n,k,w)
\approx
T_{\mathrm{core}}(n).
}
]

这就是为什么并行 leaf 可以把一个大 core 替换成一个小 core 的 wall time。

---

# 5. Split/Merge 的复杂度推导

这里需要特别区分两件事：

[
\boxed{
\text{代数上的 Split/Combine}
}
]

和

[
\boxed{
\text{带 secret/ring switching 的 Split/Merge}
}
]

HERMES 说，在 coefficients-encoded CKKS 中，Split/Combine 的 bijection 是 direct sum，因此本身只是 coefficient rearrangement，几乎没有计算成本；但是完整 ring switching 到低 degree 或高 degree 时，可能需要 key switching。

---

## 5.1 纯 coefficient rearrangement 情况

如果 Split/Merge 只是把 coefficients 重排：

[
a(X)=\sum_{r=0}^{k-1} X^r a_r(X^k),
]

则：

[
\Split_k(a)=(a_0,\ldots,a_{k-1}).
]

每个 coefficient 只被读取/写入一次。

所以一层 one-shot Split 的内存搬运复杂度是：

[
\boxed{
T_{\Split}^{\mathrm{rearrange}}(N,k)
====================================

O(L_Q N).
}
]

Merge 同理：

[
\boxed{
T_{\Merge}^{\mathrm{rearrange}}(N,k)
====================================

O(L_Q N).
}
]

如果实现是递归二叉 Split，每层都搬运全部 coefficients，一共有：

[
\ell=\log_2 k
]

层，则：

[
\boxed{
T_{\Split}^{\mathrm{rearrange-tree}}(N,k)
=========================================

O(L_Q N\log k).
}
]

Merge 同理：

[
\boxed{
T_{\Merge}^{\mathrm{rearrange-tree}}(N,k)
=========================================

O(L_Q N\log k).
}
]

这部分一般不是主瓶颈。

---

## 5.2 带 key switching 的 Split/Merge

如果 top secret 和 leaf secret 不天然匹配，或者需要 ring switching keys，那么 Split/Merge 的主要开销是 key switching。

对 (k=2^\ell)，递归 Split 是：

[
R_N
\rightarrow
2R_{N/2}
\rightarrow
4R_{N/4}
\rightarrow
\cdots
\rightarrow
kR_{N/k}.
]

第 (j) 层有：

[
2^j
]

个节点，每个节点 degree 是：

[
\frac{N}{2^j}.
]

如果每个 split node 需要 (\nu_{\Split}) 次 key switching，则：

[
\boxed{
T_{\Split}^{\mathrm{KS}}(N,k)
=============================

\sum_{j=0}^{\ell-1}
2^j\cdot
\nu_{\Split}\cdot
\mathsf{KS}\left(\frac{N}{2^j},Q,P\right).
}
]

同理：

[
\boxed{
T_{\Merge}^{\mathrm{KS}}(N,k)
=============================

\sum_{j=0}^{\ell-1}
2^j\cdot
\nu_{\Merge}\cdot
\mathsf{KS}\left(\frac{N}{2^j},Q,P\right).
}
]

如果用：

[
\mathsf{KS}(M,Q,P)
\approx
c_{\mathrm{KS}} M\log M,
]

则：

[
T_{\Split}^{\mathrm{KS}}(N,k)
\approx
\nu_{\Split}c_{\mathrm{KS}}
\sum_{j=0}^{\ell-1}
2^j\cdot
\frac{N}{2^j}
\log\left(\frac{N}{2^j}\right).
]

化简：

# [

\nu_{\Split}c_{\mathrm{KS}}
N
\sum_{j=0}^{\ell-1}
(\log N-j).
]

所以：

[
\boxed{
T_{\Split}^{\mathrm{KS}}(N,k)
\approx
\nu_{\Split}c_{\mathrm{KS}}
N
\left(
\ell\log N-\frac{\ell(\ell-1)}{2}
\right).
}
]

其中：

[
\ell=\log_2 k.
]

Merge 同理：

[
\boxed{
T_{\Merge}^{\mathrm{KS}}(N,k)
\approx
\nu_{\Merge}c_{\mathrm{KS}}
N
\left(
\ell\log N-\frac{\ell(\ell-1)}{2}
\right).
}
]

这个推导说明：

* (k=2) 时，Split/Merge 只有一层，开销约为 (O(N\log N))；
* (k=4) 时，有两层，开销约为 (O(N(2\log N-1)))；
* (k) 很大时，Split/Merge 可能成为明显开销。

---

# 6. 总体 speedup 公式

Direct：

[
T_{\mathrm{dir}}(N)
===================

T_{\mathrm{shared}}(N)
+
T_{\mathrm{core}}(N).
]

Factored：

[
T_{\mathrm{fac}}(N,k)
=====================

T_{\mathrm{shared}}(N)
+
T_{\Split}(N,k)
+
T_{\Merge}(N,k)
+
T_{\mathrm{leaf}}^\parallel(n,k,w)
+
T_{\mathrm{sync}}.
]

因此 speedup 是：

[
\boxed{
S(N,k,w)
========

\frac{
T_{\mathrm{shared}}(N)+T_{\mathrm{core}}(N)
}{
T_{\mathrm{shared}}(N)
+
T_{\Split}(N,k)
+
T_{\Merge}(N,k)
+
T_{\mathrm{leaf}}^\parallel(N/k,k,w)
+
T_{\mathrm{sync}}
}.
}
]

代入 leaf parallel model：

[
\boxed{
S(N,k,w)
========

\frac{
T_{\mathrm{shared}}(N)+T_{\mathrm{core}}(N)
}{
T_{\mathrm{shared}}(N)
+
T_{\Split}(N,k)
+
T_{\Merge}(N,k)
+
\frac{k}{\min(k,w)\eta_{\mathrm{par}}}T_{\mathrm{core}}(N/k)
+
T_{\mathrm{sync}}
}.
}
]

---

## 6.1 为什么 speedup 可以超过 (k)？

如果：

[
T_{\mathrm{core}}(d)
\approx
c d^p(\log d)^q,
]

则当 (w\ge k)、并行效率接近 1、忽略 Split/Merge/shared overhead 时：

[
S_{\mathrm{ideal}}
\approx
\frac{T_{\mathrm{core}}(N)}
{T_{\mathrm{core}}(N/k)}
========================

\frac{cN^p(\log N)^q}
{c(N/k)^p(\log(N/k))^q}.
]

所以：

[
\boxed{
S_{\mathrm{ideal}}
\approx
k^p
\left(
\frac{\log N}{\log(N/k)}
\right)^q.
}
]

如果 (p=1)，那么 speedup 约为 (k)。
如果 (p>1)，speedup 可以超过 (k)。

你的 (\log N=17,k=2) 实验中，single-run timing 是：

[
T_{\mathrm{dir}}=117.207541s,
]

[
T_{\mathrm{fac}}=23.303824s,
]

[
S=5.0295\times.
]

这明显超过 (2\times)，说明 direct large-ring bootstrapping 在当前实现和机器上呈现明显超线性增长；日志同时显示 C2S alignment、EvalMod alignment 和最终 RAW 对齐都成立，输出 level 也都是 10。

---

## 6.2 为什么实际 speedup 会低于理想值？

因为 factored 版本有额外项：

[
T_{\Split}
+
T_{\Merge}
+
T_{\mathrm{sync}}
+
T_{\mathrm{shared}}(N).
]

其中 (T_{\mathrm{shared}}(N)) 在 direct 和 factored 两边都存在，不能被 leaf 并行消掉。

这就是 Amdahl 限制：

[
\boxed{
S
\le
\frac{1}
{
f_{\mathrm{shared}}
+
f_{\mathrm{SM}}
+
(1-f_{\mathrm{shared}}-f_{\mathrm{SM}})/S_{\mathrm{core}}
}.
}
]

其中：

* (f_{\mathrm{shared}})：ScaleDown/ModUp 占比；
* (f_{\mathrm{SM}})：Split/Merge 占比；
* (S_{\mathrm{core}})：核心 C2S/EvalMod/S2C 的加速比。

---

# 7. Key size 开销

HERMES 给出的 elementary switching key 大小模型是：

[
\boxed{
|\mathrm{swk}_{d,qp}|
\approx
2d\log(qp)
}
]

因为一个 switching key 是 degree-(d)、modulus (qp) 下的 RLWE ciphertext。

在 RNS 实现中更工程化地写：

[
|\mathrm{swk}_{d,QP}|
\approx
2\cdot d\cdot (L_Q+L_P)\cdot 8
\quad \text{bytes}
]

再乘上 decomposition number、key component 数、是否 seed 压缩等常数。

---

## 7.1 Direct key size

Direct bootstrapping key size 可以写为：

[
\boxed{
\mathrm{KeySize}_{\mathrm{dir}}
===============================

|\mathrm{BTSKeys}_N|.
}
]

更细：

[
|\mathrm{BTSKeys}_N|
====================

|\mathrm{RotKeys}*{\CtwoS,N}|
+
|\mathrm{RotKeys}*{\StwoC,N}|
+
|\mathrm{RelinKeys}_N|
+
|\mathrm{OtherEvalKeys}_N|.
]

如果每个 rotation key 大小近似是：

[
\mathsf{Key}(N,QP),
]

则：

[
|\mathrm{RotKeys}*{\CtwoS,N}|
\approx
\rho*{\CtwoS}(N)\cdot \mathsf{Key}(N,QP),
]

[
|\mathrm{RotKeys}*{\StwoC,N}|
\approx
\rho*{\StwoC}(N)\cdot \mathsf{Key}(N,QP).
]

所以：

[
\boxed{
\mathrm{KeySize}*{\mathrm{dir}}
\approx
\left(
\rho*{\CtwoS}(N)+\rho_{\StwoC}(N)+\rho_{\mathrm{other}}(N)
\right)
\mathsf{Key}(N,QP).
}
]

HERMES Table 2 给了一个可参考的 bootstrapping key 量级：HEaaN FGb 参数中 (N=2^{16})、(\log_2(QP)=1555)，bootstrapping key size 是 667MB，单线程 bootstrapping 时间 27.4s。

---

## 7.2 Factored key size

Factored 版本：

[
\boxed{
\mathrm{KeySize}_{\mathrm{fac}}
===============================

|\mathrm{SplitMergeKeys}*{N,k}|
+
\eta*{\mathrm{key}}\cdot|\mathrm{BTSKeys}_n|.
}
]

这里 (\eta_{\mathrm{key}}) 很关键：

[
\eta_{\mathrm{key}}
===================

\begin{cases}
1, & \text{所有 leaves 共享同一套 leaf BTS keys},\
k, & \text{每个 leaf 使用独立 secret / 独立 key set}.
\end{cases}
]

如果 leaf evaluators 只是多个 worker 共享同一套 leaf key，那么：

[
\boxed{
\mathrm{KeySize}*{\mathrm{fac}}
\approx
|\mathrm{SplitMergeKeys}*{N,k}|
+
|\mathrm{BTSKeys}_n|.
}
]

如果每个 leaf 都有独立 secret 和 keys：

[
\boxed{
\mathrm{KeySize}*{\mathrm{fac}}
\approx
|\mathrm{SplitMergeKeys}*{N,k}|
+
k|\mathrm{BTSKeys}_n|.
}
]

---

## 7.3 Split/Merge keys

如果 Split/Merge 只做 coefficient rearrangement：

[
|\mathrm{SplitMergeKeys}_{N,k}|\approx0.
]

如果需要 key switching，则：

[
|\mathrm{SplitMergeKeys}*{N,k}|
\approx
\sum*{j=0}^{\ell-1}
2^j\cdot
\nu_{\mathrm{SM},j}
\cdot
\mathsf{Key}\left(\frac{N}{2^j},QP\right).
]

若：

[
\mathsf{Key}(M,QP)\approx 2M\log(QP),
]

则：

[
|\mathrm{SplitMergeKeys}*{N,k}|
\approx
\sum*{j=0}^{\ell-1}
2^j\cdot
\nu_{\mathrm{SM},j}
\cdot
2\frac{N}{2^j}\log(QP).
]

若每层 (\nu_{\mathrm{SM},j}\approx\nu_{\mathrm{SM}})，则：

[
\boxed{
|\mathrm{SplitMergeKeys}*{N,k}|
\approx
2\nu*{\mathrm{SM}}N\log(QP)\log_2 k.
}
]

也就是说，Split/Merge key size 至少会随：

[
N\log(QP)\log k
]

增长。

# 8. Memory 开销

密文大小近似：

[
\boxed{
\mathsf{CT}(d,L_Q)
\approx
2dL_Q\cdot 8
\quad \text{bytes}
}
]

因为 degree-1 RLWE ciphertext 有两个多项式。

Key switching 临时进入 (QP) basis：

[
\boxed{
\mathsf{CT}_{QP}(d,L_Q,L_P)
\approx
2d(L_Q+L_P)\cdot 8.
}
]

Direct peak memory 可写为：

[
\boxed{
M_{\mathrm{dir}}
================

M_{\mathrm{keys,dir}}
+
M_{\mathrm{work,dir}}(N).
}
]

Factored peak memory：

[
\boxed{
M_{\mathrm{fac}}
================

M_{\mathrm{keys,fac}}
+
M_{\mathrm{shared}}(N)
+
M_{\Split/\Merge}(N,k)
+
w\cdot M_{\mathrm{leafWork}}(n).
}
]

这说明：

* 每个 leaf 更小，cache locality 更好；
* 但并行 (w) 个 leaf 会让 working memory 乘以 (w)；
* Split/Merge 还需要中间 ciphertext buffers；
* key material 可能更小，也可能更大，取决于 leaf keys 是否共享。

所以你的性能汇报里，除了 time，还应该报告：

[
\boxed{
\text{Direct peak memory}
\quad \text{vs}\quad
\text{Factored peak memory}.
}
]

否则只看时间不完整。

# 9. 安全参数带来的复杂度开销

这是你的方案里非常重要的 hidden cost。

因为 leaf 不是自动继承 top 的安全性。若 leaf 真正在 (R_n) 上做 bootstrapping，则 leaf 安全性主要看：

[
(n,\log(QP)).
]

HERMES 也明确指出，可以降低 degree，但限制是 lowered degree 和 switching-key modulus 下仍然安全；换句话说，degree 可以降，但不能降到当前 modulus 下不安全的程度。

所以你的安全版不能随便用：

[
\log N=16,\quad k=4,\quad \log n=14,\quad \log(QP)\approx1520.
]

如果想让 leaf 仍然承载 bootstrapping 级别的：

[
\log(QP)\approx1520,
]

更合理的是：

[
\boxed{
\log n_{\mathrm{leaf}}=16.
}
]

于是：

* 安全 (k=2)：

[
\log N_{\mathrm{top}}=17,\quad \log n=16.
]

* 安全 (k=4)：

[
\log N_{\mathrm{top}}=18,\quad \log n=16.
]

这意味着：为了安全拆分，top (N) 可能需要比原 direct baseline 更大。

因此复杂度比较必须分两类。

---

## 9.1 同一 top problem 的公平比较

这是算法内部公平比较：

[
\boxed{
\text{Direct BTS at }N
\quad
\text{vs}
\quad
\text{Factored BTS at same }N,k.
}
]

例如你的安全版：

[
\log N=17,\quad k=2,\quad \log n=16.
]

日志显示：

[
117.207541s
\rightarrow
23.303824s,
\qquad
5.0295\times.
]

这是你的主结果。

---

## 9.2 吞吐量公平比较

因为：

[
\log N=17
]

有：

[
2\times
]

(\log N=16) 的 slots，所以应用层还应该比较：

[
\boxed{
T_{\mathrm{fac}}(2^{17},k=2)
\quad
\text{vs}
\quad
2T_{\mathrm{dir}}(2^{16}).
}
]

这回答的是：

> 用一个大 ciphertext 做 factored bootstrapping，是否比处理两个 leaf-size direct ciphertext 更划算？

这对 neural network batch inference / high-throughput 场景尤其重要。

# 11. 和 HERMES 的关系

你应该这样定位：

[
\boxed{
\text{HERMES 提供 Split/Combine/ring switching backend。}
}
]

[
\boxed{
\text{你的工作是在这个 backend 上做 no-}B_k\text{ bootstrapping core factorization。}
}
]

HERMES 的完整目标是 ring packing：

[
\text{many LWE/MLWE ciphertexts}
\rightarrow
\text{one RLWE ciphertext}.
]

它的流程是：

[
\text{base ring packing at low modulus}
\rightarrow
\text{ring switching}
\rightarrow
\text{HalfBTS}.
]

论文中 HERMES 描述为：先 base ring pack 到较小 degree 的 RLWE ciphertexts，再用 ring switching 合成 degree (N_{\mathrm{BTS}}) 的 ciphertext，最后 HalfBTS 到高模数。

你的流程不同：

[
\text{one large CKKS ciphertext}
\rightarrow
\Split
\rightarrow
\text{leaf BTS cores}
\rightarrow
\Merge.
]

所以你的贡献不是 ring switching 本身，而是：

[
\boxed{
\text{发现 CKKS bootstrapping core 可以通过 coefficient split 做 no-}B_k\text{ 分解。}
}
]

更具体：

[
\BTS_N^{\mathrm{dir}}
=====================

\StwoC_N\circ\EvalMod_N\circ\CtwoS_N.
]

[
\BTS_{N,k}^{\mathrm{fac}}
=========================

\Merge_k
\circ
\left(
\bigoplus_{r=0}^{k-1}
\StwoC_n\circ\EvalMod_n\circ\CtwoS_n
\right)
\circ
\Split_k.
]

HERMES 给你的是：

1. (R_{q,N}) 作为 (R_{q,n})-module 的代数解释；
2. Split/Combine 的 direct-sum 解释；
3. ring/key switching 的 ModUp/MultSwk/ModDown 复杂度模型；
4. 降低 degree 必须满足当前 modulus 下安全性的原则。

# 12. 最终复杂度结论

可以把你的复杂度结论浓缩成下面这个 theorem-style statement。

## Theorem-style complexity statement

设 (n=N/k)，(k=2^\ell)。令：

[
T_{\mathrm{core}}(d)
====================

T_{\CtwoS}(d)+T_{\EvalMod}(d)+T_{\StwoC}(d).
]

Direct full bootstrapping cost is:

[
\boxed{
T_{\mathrm{dir}}(N)
===================

T_{\mathrm{shared}}(N)+T_{\mathrm{core}}(N).
}
]

Factored no-(B_k) full bootstrapping cost is:

[
\boxed{
T_{\mathrm{fac}}(N,k)
=====================

T_{\mathrm{shared}}(N)
+
T_{\Split}(N,k)
+
T_{\Merge}(N,k)
+
\frac{k}{\min(k,w)\eta_{\mathrm{par}}}
T_{\mathrm{core}}(N/k)
+
T_{\mathrm{sync}}.
}
]

If Split/Merge require key switching, then:

[
\boxed{
T_{\Split}(N,k)
+
T_{\Merge}(N,k)
===============

O!\left(
N
\left(
\ell\log N-\frac{\ell(\ell-1)}{2}
\right)
\cdot (L_Q+L_P)
\right).
}
]

If Split/Merge are pure coefficient rearrangements, then:

[
\boxed{
T_{\Split}(N,k)+T_{\Merge}(N,k)
===============================

O(L_QN\log k)
}
]

or even (O(L_QN)) if implemented one-shot.

If:

[
T_{\mathrm{core}}(d)\approx c d^p(\log d)^q,
\qquad p>1,
]

and (w\ge k), then ideal speedup is approximately:

[
\boxed{
S
\approx
k^p
\left(
\frac{\log N}{\log(N/k)}
\right)^q
}
]

up to shared-cost and Split/Merge overhead.

This explains why your (\log N=17,k=2) experiment can show (5.03\times) speedup rather than being capped near (2\times).

# 14. 一句话总结

你的复杂度分析最终可以这样讲：

[
\boxed{
\text{Direct bootstrapping 在大 ring }N\text{ 上执行完整 } \CtwoS\text{--}\EvalMod\text{--}\StwoC\text{ core。}
}
]

[
\boxed{
\text{Factored no-}B_k\text{ 保留 top-level ScaleDown/ModUp，但用 HERMES-style Split/Merge 将 core 拆到 }n=N/k\text{ 的 leaves。}
}
]

[
\boxed{
\text{收益来自 }T_{\mathrm{core}}(N)\text{ 的超线性下降和 leaf 并行；代价来自 Split/Merge key switching、额外 keys、parallel memory 和安全参数导致的 top }N\text{ 增大。}
}
]

这套分析已经可以支撑你的汇报。下一步最值得补的是 per-stage timing 和 key/memory size，这样就能把公式里的每一项都用实测数据填上。
