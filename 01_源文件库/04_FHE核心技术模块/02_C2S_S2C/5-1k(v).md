好，我们现在就只讲：

# (\kappa(v)) 到底怎么求

而且只讲这件事。

---

# 1. 先说它在干什么

我们已经知道，论文把一个“逐槽作用的线性变换”写成

[
L(m)=\sum_{v=0}^{d-1}\kappa(v),\sigma^v(m).
]

这里：

* (\sigma^v) 是第 (v) 次 Frobenius 算子；
* (\kappa(v)) 是你要预先算出来的“权重”。

所以“求 (\kappa(v))”的本质就是：

> **我要找一组权重，让右边这堆 Frobenius 幂的线性组合，恰好等于我想要的目标变换 (L)。**

如果这里的 (L) 取成 (M)，那就是在求实现 (M) 的那组 (\kappa(v))。

---

# 2. 先把问题降到“单个槽”里

因为 (L) 是 slot-wise 的，所以我们只看一个槽就够了。

设单个槽里的元素空间是 (E)。
在这个槽里，我们已经固定了一个基，比如

[
1,\zeta_m,\zeta_m^2,\dots,\zeta_m^{d-1}.
]

那么：

* 目标变换 (L) 在这个基下可以写成一个 (d\times d) 矩阵；
* 每个 (\sigma^v) 在这个基下也可以写成一个 (d\times d) 矩阵。

于是“求 (\kappa(v))”就变成了：

[
L = \sum_{v=0}^{d-1} \kappa(v), S_v,
]

其中 (S_v) 是 (\sigma^v) 的矩阵。

这就是一个**线性方程组**。

---

# 3. 最直接的普通线性代数版本

先别带任何密码学，假设你有：

* 一个目标矩阵 (L)
* 一堆固定矩阵 (S_0,S_1,\dots,S_{d-1})

你想找系数 (\kappa(0),\dots,\kappa(d-1))，使得

[
L=\kappa(0)S_0+\kappa(1)S_1+\cdots+\kappa(d-1)S_{d-1}.
]

最朴素的做法就是：

1. 把每个矩阵拉直成一个长向量；
2. 把这些向量当作列拼成一个大矩阵；
3. 把 (L) 拉直成右端向量；
4. 解线性方程组。

这就是最直接的“怎么算 (\kappa(v))”。

---

# 4. 但论文这里其实更自然的做法，不是看矩阵，而是看“对基向量的作用”

因为线性变换只要知道它对一组基的作用就完全确定。

所以我们不一定真的把整个矩阵拉直。
我们也可以这样做：

设槽里的基是

[
e_0=1,\quad e_1=\zeta_m,\quad \dots,\quad e_{d-1}=\zeta_m^{d-1}.
]

我们知道目标变换 (L) 对这些基向量应该怎么作用：

[
L(e_j)\quad (j=0,\dots,d-1)
]

同时每个 (\sigma^v) 对这些基向量的作用也知道：

[
\sigma^v(e_j).
]

于是要求

[
L(e_j)=\sum_{v=0}^{d-1}\kappa(v),\sigma^v(e_j)
\qquad
\text{对每个 }j.
]

这就是一组方程。
把 (j=0,\dots,d-1) 全部列出来，就得到求 (\kappa(v)) 的线性系统。

---

# 5. 具体到 (M)，目标方程长什么样

现在把 (L) 换成 (M)。

(M) 的目标是在第 (i) 个槽里把

[
\zeta_{m,i}^j \mapsto \zeta_m^j.
]

如果我们站在“统一基”这一边来描述，那么 (M) 就是一个明确已知的换基变换。

所以求 (\kappa(v)) 的步骤是：

## 第一步

把 (M) 写成该槽上的线性变换矩阵 (L_i)。

也就是先知道：对槽里的每个基向量 (e_j)，(M) 应该输出什么。

## 第二步

把每个 (\sigma^v) 也写成该槽上的矩阵 (S_v)。

## 第三步

解

[
L_i=\sum_{v=0}^{d-1}\kappa_i(v),S_v.
]

解出来的 (\kappa_i(v))，就是这个槽上实现 (M_i) 的权重。

---

# 6. 为什么 (\kappa(v)) 不是一个普通标量那么简单

这里你前面其实已经意识到了：
如果 (\kappa(v)) 只是一个普通数，自由度未必够。

论文里真正的 (\kappa(v)) 是 plaintext ring 里的常数项对象，用来乘密文。也就是说，它们本身可以在不同槽上表现出不同值。

这点非常重要，因为 (M) “depends on (i)”——也就是不同槽上对应的换基不同。

所以同一个 (\kappa(v)) 作为明文常数乘到密文上时，本质上可以被理解为：

* 在槽 0 上取某个值；
* 在槽 1 上取另一个值；
* …
* 从而同时编码了各槽不同的权重。

所以真正求 (\kappa(v)) 时，不是每个 (\kappa(v)) 只有一个数，而是它在所有槽上的取值都要一起求。

---

# 7. 最朴素的“按槽求值，再 CRT 拼回去”版本

这是最容易懂的算法思路。

因为 (M) 是 slot-wise 的，所以可以分槽来定。

对于每个固定的 (v)：

1. 先在每个槽 (i) 上，求出这个槽所需的系数
   [
   \kappa_i(v)
   ]
   使得
   [
   M_i=\sum_{v=0}^{d-1}\kappa_i(v)\sigma^v.
   ]

2. 然后再找一个总明文常数 (\kappa(v)\in R_{p^e})，使得它在第 (i) 个槽里的值正好等于 (\kappa_i(v))。

也就是说：

[
\kappa(v)\ \text{在槽 }i\text{ 上的投影}=\kappa_i(v).
]

这一步本质上又是一次 CRT 插值。

所以你可以把“求 (\kappa(v))”理解成两层：

* **槽内**：先求每个槽自己的权重 (\kappa_i(v))
* **整体**：再用 CRT 把这些槽值拼成一个总明文常数 (\kappa(v))

---

# 8. 这个过程为什么合理

因为一个 plaintext 常数在 ring 里虽然是一个对象，但按槽看就是一个向量：

[
(\text{槽0值},\text{槽1值},\dots).
]

所以只要你先规定了它在每个槽上应该是多少，就能通过 CRT 唯一拼回一个总对象。
这和你前面学过的“用 (H_iG_i) 拼槽值”是同一个思想。

所以 (\kappa(v)) 的真正来源其实很清楚：

> 它是“把各槽里所需的局部系数 (\kappa_i(v)) 打包成一个总明文常数”的结果。

---

# 9. 一个二维普通线性代数类比

假设有两个“槽”，每个槽都是一维空间。
某个算子模板是

[
L(x)=\kappa(0)x+\kappa(1)F(x),
]

并且：

* 在槽 0 上你需要的系数是 (\kappa_0(0),\kappa_0(1))
* 在槽 1 上你需要的系数是 (\kappa_1(0),\kappa_1(1))

那就构造总权重：

* (\kappa(0))：在槽 0 上值为 (\kappa_0(0))，在槽 1 上值为 (\kappa_1(0))
* (\kappa(1))：在槽 0 上值为 (\kappa_0(1))，在槽 1 上值为 (\kappa_1(1))

这样乘到整个密文上时，就自动“逐槽拿到正确权重”。

这就是论文里 (\kappa(v)) 的工作方式，只不过槽内空间更高维，算子是 (\sigma^v)。

---

# 10. 所以“怎么算 (\kappa(v))”最准确的回答

你现在可以把它记成：

> **先把目标槽内变换 (M_i) 在每个槽上展开到 Frobenius 幂 (\sigma^v) 上，解出每个槽自己的系数 (\kappa_i(v))；再把这些槽值通过 CRT 拼成一个总明文常数 (\kappa(v))。**

这就是最朴素、最本质的求法。

---

# 11. 论文为什么没把这步写成特别长的显式公式

因为论文更关心的是：

* 这种表示存在；
* 因而 (M) 和 (M^{-1}) 可以按第 2.4.2 节的 slot-wise linear transformation 模板实现；
* 再据此分析复杂度。第 5.1.1 节就是这么做的。

也就是说，论文更偏“实现框架 + 复杂度分析”，没有把每个 (\kappa(v)) 的线性系统展开成长篇公式。

---

# 12. 一句最关键的总结

> **(\kappa(v)) 不是凭空写出来的；它是通过“把目标槽内换基变换 (M) 展开到 Frobenius 幂 (\sigma^v) 上”解出来的权重。最朴素的做法是：先在每个槽里解出局部系数 (\kappa_i(v))，再用 CRT 把这些局部系数拼成总明文常数 (\kappa(v))。**
