# Research-KB-RAG 使用导读

这是一个个人研究知识库与论文协作系统，用来管理研究资料、知识卡片、论文项目、实验材料和本地 RAG 检索流程。

它不是一个普通的文件夹，而是一个长期维护的研究工作台。  
使用时建议先理解三个核心思想：

1. **原始资料先归档**：论文、笔记、PDF、实验日志先放到源文件或论文项目区。
2. **稳定知识再沉淀**：只有经过确认、可复用的内容才进入知识卡片和 Q&A。
3. **RAG 只检索 ready 内容**：未验证的想法、候选结论、论文 open problem 不应直接进入 RAG ready。

## 4. 人类日常怎么用

### 4.1 查资料

优先使用 RAG：

```bash
cd ~/Desktop/Research-KB-RAG/06_RAG入库准备/api_rag
python3 query_rag.py "你的问题" -k 5 -v
```

建议：

- 普通问题用 `-k 5`
- 大范围论文问题用 `-k 10`
- 主要看 top-3
- top-4/top-5 只作为补充
- 如果问题涉及 proof、安全、噪声或未验证结论，不要直接相信检索结果，需要人工判断

---

### 4.2 新增一份资料

比如你下载了一篇新论文，或者写了一份新笔记。

推荐流程：

1. 把原始文件放到合适的源文件目录，例如：

   ```text
   01_源文件库/
   ```

   或者如果它只属于某篇论文项目，放到对应论文项目目录。

2. 更新导入记录：

   ```text
   00_导入记录/导入清单.md
   ```

3. 判断这份资料是否需要整理成知识卡片。

4. 如果只是暂存资料，不需要马上做卡片，也不需要更新 RAG。

5. 如果整理出了稳定知识，再进入“新增知识卡片”流程。

---

### 4.3 新增知识卡片

当某个知识点已经稳定、可复用、不是只属于某篇论文的猜想时，可以生成知识卡片。

推荐流程：

1. 在 `02_知识卡片/` 中创建新卡片。
2. 补充必要字段，例如：
   - card_id
   - title
   - source_id
   - confidence
   - knowledge_status
   - rag_status
3. 更新全局索引：
   - `09_工作进度/全局知识卡片索引.md`
   - `09_工作进度/canonical_card_manifest.jsonl`
4. 判断是否进入 RAG：
   - 如果是 ready 知识，可以进入 RAG ready
   - 如果还需要人工确认，保持 defer
5. 如果进入 RAG ready，则需要重建 chunks、embeddings 和 BM25。

---

### 4.4 新增原子问答

原子问答适合保存“一个问题 + 一个清晰回答”。

推荐流程：

1. 在 `03_原子问答/` 中新增 Q&A。
2. 关联对应 source_id 和 card_id。
3. 更新：
   - `09_工作进度/全局原子问答索引.md`
   - `09_工作进度/canonical_qa_manifest.jsonl`
4. 判断是否进入 RAG ready。
5. 只有 ready Q&A 进入 chunks 后，才需要重建 embeddings 和 BM25。

---

### 4.5 新增论文 idea

论文 idea 不要直接进入正式知识库。

推荐流程：

1. 放入当前论文项目：

   ```text
   04_论文协作区/01_当前论文项目/<paper_id>/09_知识沉淀候选/
   ```

2. 同步登记到：

   ```text
   11_知识入库接口/candidate_knowledge总表.md
   ```

3. 标记为 candidate / needs_validation。
4. 不进入 RAG ready。
5. 等作者确认后，才可以升级为正式知识卡片。

---

### 4.6 新增一个论文项目

推荐流程：

1. 在 `04_论文协作区/01_当前论文项目/` 或未来项目区创建新项目目录。
2. 使用标准结构：

   ```text
   00_项目管理/
   01_论文正文/
   02_核心构造/
   03_证明系统/
   04_实验实现/
   05_参数与安全/
   06_Related_Work/
   07_图表与表格/
   08_待确认问题/
   09_知识沉淀候选/
   10_发布快照/
   11_AI工作区/
   README.md
   ```

3. 更新：

   ```text
   04_论文协作区/00_论文项目总索引.md
   ```

4. 在新项目的 `README.md` 中说明：
   - 论文目标
   - 当前状态
   - 主要入口
   - 哪些问题需要人工确认
5. 新论文项目中的 idea 默认是 candidate，不直接进入 RAG ready。

## 5. 什么时候需要重建 RAG

不要因为每次整理文件就重建 RAG。

### 不需要重建 RAG 的情况

这些通常不需要重建 embeddings：

- 只是移动文件
- 只是复制论文材料
- 只是更新 README
- 只是更新 SOP
- 只是新增 AI 工作区说明
- 只是新增论文 candidate
- 只是新增实验原始日志
- 只是整理目录结构

### 需要重建 RAG 的情况

这些情况需要重建 embeddings 和 BM25：

- ready card 正文变了
- ready Q&A 正文变了
- ready chunks 重新生成
- 新增 ready card
- 新增 ready Q&A
- 删除或排除 ready chunk
- 修正会影响检索答案的核心术语

重建命令：

```bash
cd ~/Desktop/Research-KB-RAG/06_RAG入库准备/api_rag
python3 build_embeddings.py
python3 build_bm25_index.py
```

重建后建议运行 smoke test：

```bash
python3 query_rag.py "C2S 和 S2C 的方向是什么？" -k 5 -v
python3 query_rag.py "ModSwitch、Rescale、KeySwitch 三者有什么区别？" -k 5 -v
python3 query_rag.py "K063" -k 5 -v
```

## 6. 什么内容不能直接当成正式结论

以下内容不能直接当成 validated knowledge：

- candidate knowledge
- needs_human_review
- low confidence
- 论文 open problem
- 未验证实验观察
- proof 草稿
- 噪声分析草稿
- 安全性猜想
- 作者还没确认的主定理或贡献声明

如果材料不足，应该写：

```text
当前知识库没有 validated 结论，只能提供相关背景材料和待确认点。
```

## 8. 推荐工作流

### 普通整理

用便宜模型或普通 AI：

1. 整理文件
2. 总结材料
3. 生成 README
4. 维护索引
5. 处理长上下文

### 关键数学推导

用高质量模型和人工确认：

1. 先用 RAG 检索 top-5
2. 把相关材料交给 GPT
3. 要求检查 proof gap
4. 不允许编造定理
5. 最终结论由作者确认

### 写论文

进入论文项目目录：

```text
04_论文协作区/01_当前论文项目/Eurocrypt2027/
```

优先看：

```text
01_论文正文/
02_核心构造/
03_证明系统/
05_参数与安全/
08_待确认问题/
```

## 9. 一句话总结

这个仓库的目标不是把所有资料堆在一起，而是形成一个可长期维护的研究系统：

```text
原始资料 → 知识卡片 / Q&A → RAG 检索 → 论文协作 → 人工确认 → 长期知识沉淀
```

使用时最重要的是：

- 原始资料和正式知识分开
- 论文 idea 和 validated knowledge 分开
- AI 工作区和论文正文分开
- RAG ready 和 candidate/defer 分开
- 普通整理和关键数学判断分开
